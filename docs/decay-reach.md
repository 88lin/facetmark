# 够不着的衰减层，代价是多少

> **更正（1.6.0，2026-08-05）：这份文档的主结论已被推翻。下面的正文一字未改，保留作为
> 记录。**
>
> 本文 §7 最后一条自陈「健康检查的覆盖率没有量」。后来量了：这个库的 `health` 表有
> **0 行**，健康检查器从来没跑过，所以冷层三条件里靠健康判定的那一半**从来没有可能
> 触发**（另外 `open_count` 全库为 0，条件 1 也是恒真的）。下面「冷层只有 8 页」这个
> 数字是在一台没开机的仪器上读出来的。
>
> 跑完健康检查重做同一个 A/B：冷层 **8 → 73**，冷层与目标集的交集 **0 → 8**，
> **ΔRecall@5 从 `+0.0000pp` 变成 `−1.4610pp`，CI95 `[−2.5974, −0.4870]`**。也就是说
> 这个「缺陷」实际在**帮忙**，修掉它要付 1.46pp。
>
> 结论（不改阈值）没变，理由全变了。完整过程、机制拆解和根因见
> **`docs/decay-instrumented.md`**。本文 §5「救援阀守着一个不存在的风险」和 §6「收益是
> 零」两处应视为**已作废**。

`tests/test_decay_reach.py` 用五条测试证明了一件事：默认档里的冷层降权**从来没有执行
过**。这份文档回答它没回答的那个问题——**那又怎么样**。

结论先写在这里：**缺陷是真的（616 条查询里 113 条本该降权而没有降），代价是零。**
Recall@5 的差是 `0.0000pp`，CI95 `[0, 0]`，而且这不是「样本不够看不出差别」，是逐条
比对之后**一条查询的对错都没有改变**。

更有用的是为什么。真正让这一层失效的不是那个阈值，是**冷层本身几乎是空的**：全库
2,376 页里满足降权条件的只有 **8 页**。修阈值不会让这一层变得有用。

## 1. 缺陷

RRF 给出的分数是 `sum_f w_f / (k + rank_f)`。`rrf_k = 60`，所以一个单位权重的面能给出
的最高分是 `1 / 61 = 0.016393`。出厂的 `decay_rescue_threshold` 是 `0.02`。

`FULL`——配了 API key 时的**默认档**——是单面配置（`frozenset({"content"})`）。于是
`apply_decay` 里的 `hot_top_score < rescue_threshold` 恒成立，救援阀每次都开，它守着
的那个降权一次也没执行。四面的 `FUSED` 不受影响：两个面就有 `1.7 / 61 = 0.0279`。

这是一个关于算术的证明。它不说后果。「默认档里有一层死代码」和「默认档因此排得更差」
是两个不同的主张，这份文档测的是第二个。

## 2. 方法

确定性 A/B，同一个检索器只改一个设置：

| | `decay_rescue_threshold` | 效果 |
|---|---|---|
| shipped | `0.02` | 出厂值，阀门每次都开，降权从不执行 |
| reachable | `0.0` | 阀门永远开不了（分数非负），降权总是执行 |

同一个库、同一批查询、同一个嵌入模型、同一套融合、时钟冻结在 `1785649110`。**两次运行
之间的每一处差异都只可能由衰减层造成**，所以归因不需要任何统计工具。下面那个 bootstrap
区间是在回答另一个问题——从这批查询推广到别的查询——不是在回答差异是否真实。

- 库：`library-w1-indexed.db`，2,376 篇，本地 bge-m3（`FACETMARK_EMBED_DIM=1024`）
- 查询：`eval/queries/w2w3-holdout.jsonl`，616 条留出集，230 个目标页
  （q_content 181 / q_vague 211 / q_episodic 224）
- 档位：`full`，`limit=20`
- 驱动：`scripts/decay_reach_probe.py`，全部数字落在 `eval/decay-reach.json`
- 测量装置本身由 `tests/test_decay_reach_probe.py`（19 条）钉住：两个档位只差
  `decay_rescue_threshold` 一个字段且读同一个库文件、`SHIPPED` 仍等于出厂默认、普查
  数的是条件 3 而不是年龄、bootstrap 是配对的（这条见 §5）、回放循环把名次记成 1 起步
  而缺席记成 0

**这个测量为什么没有预注册协议**：它不是假设检验。判据不是「Δ 超过某个线就采纳」，
输出是两个列表的逐条穷举比对，两边都跑完之前没有任何自由度可以事后调整。真要**据此
改默认排序**，那才需要协议——而下面的结论恰恰是不改。

一处要标注的例外：**Recall@1 是看到数字之后才去算的**，属于探索性指标，不能当作证据
使用。写在这里是因为藏起来更糟。

## 3. 冷层普查

降权要求**三个条件全部成立**：从未打开、保存超过 `decay_age_days = 365` 天、**并且**
有被取代的正面证据（一条 `supersession` 出边，或者一次 `gone`/`drifted`/`soft_gone`
的健康判定）。

| | 页数 |
|---|---|
| 全库 | 2,376 |
| 仅满足条件 1+2（老且从未打开） | **1,071** |
| 三条全满足（冷层） | **8** |
| 冷层 ∩ 616 条查询的 230 个目标 | **0** |

条件 3 把 1,071 砍到 8，挡掉了 **99.25%**。这条件是设计里最重要的一环——没有它，这就
是一个年龄过滤器，而年龄过滤器会精准地降权那些越老越有用的东西（语言规范、论文、
菜谱）。但它同时意味着这一层的作用面是全库的 **0.34%**。

冷层与目标集的交集是**空的**，这一点决定了后面所有的数字：降权只能把非答案往下推。

## 4. 结果

| | shipped `0.02` | reachable `0.0` |
|---|---|---|
| Recall@5 | **0.5860** | **0.5860** |
| Recall@1 | 0.4237 | 0.4253 |
| 救援阀打开的查询数 | **113 / 616** | 0 / 616 |

- **ΔRecall@5 = `+0.0000pp`，CI95 `[0.0000, 0.0000]`**
- ΔRecall@1 = `+0.1623pp`，CI95 `[0.0000, +0.4870]`（探索性）

分层的 Recall@5 一位都没动：

| 类型 | n | shipped | reachable |
|---|---|---|---|
| q_content | 181 | 0.9061 | 0.9061 |
| q_vague | 211 | 0.6540 | 0.6540 |
| q_episodic | 224 | 0.2634 | 0.2634 |

而列表确实变了：

| | 条数 |
|---|---|
| 候选列表里出现过冷页 | 46 / 616 |
| 冷页进了前 5 | 15 / 616 |
| 完整列表（top-20）发生变化 | **46** |
| 前 5 发生变化 | **15** |
| **目标名次发生变化** | **3** |

三条全部：

| 查询 | 类型 | 名次 |
|---|---|---|
| 去年换新电脑需要装软件存的 | q_episodic | 14 → 13 |
| reading about technology and jobs in 2026 | q_episodic | 9 → 8 |
| calibre 支持 哪些 电子书 格式 转换 | q_content | **2 → 1** |

Recall@1 那 `+0.1623pp` 就是最后这一条，`1/616`。

## 5. 解读

**降权在做事，只是做的事不改变对错。** 46 条查询的列表被重排了，15 条的前 5 被重排了，
但因为冷层里一个答案都没有，被推下去的全是非答案，而空出来的位置由别的非答案顶上。
目标要么本来就在冷页前面（名次不变），要么被推上来一格但仍在同一个 Recall 桶里
（14→13、9→8）。只有一条恰好跨过了 `@1` 的桶边界。

**救援阀守着一个不存在的风险。** 它的设计意图是「唯一的好答案恰好是冷页时不要把它埋
了」。在这个库上，好答案从来不是冷页——230 个目标，0 个命中冷层。所以阀门在 113 条
查询上开启，每一次保护的都是一个不需要保护的情况。

**这不是功效不足。** 一个「测不出差别」的实验通常意味着样本太小；这里不是。差是逐条
穷举出来的精确零：616 条查询里，`0 < rank <= 5` 这个布尔值一条都没翻转。CI 是 `[0,0]`
因为每一次 bootstrap 重抽都在重抽一堆完全相同的配对。

这个读法依赖 bootstrap 是**配对**的——不配对的话「10 条变好、10 条变坏」也会给出 `0.0`
的点估计，而那和「什么都没变」完全是两回事。`tests/test_decay_reach_probe.py` 里有一条
测试专门钉这件事：相互抵消的差异必须给出一个跨过零的非退化区间，只有真正一条都没变的
时候区间才会塌成 `[0, 0]`。

**所以真正的病灶不是阈值。** 就算把 `decay_rescue_threshold` 调到能触发，或者把
`rrf_k` 调小让分数抬上去，这一层能作用的仍然只有 8 页。要让衰减层有意义，得动条件 3，
而条件 3 正是拦着它退化成年龄过滤器的那道墙。这是一个远比调阈值危险的改动，而且这份
数据一点都没有支持它：**没有任何证据表明那 1,071 页里的多数该被降权。**

## 6. 结论

**不改阈值。** 理由从「改默认排序需要先有协议」升级成「已经量过了，收益是零」。

`tests/test_decay_reach.py` 继续钉住现状——它钉的是「这一层够不着」这个事实，不是
「这一层应该够不着」这个主张。哪天有人把冷层判定改宽了，那五条测试就该翻，而翻之前
应该先回来重跑一次这份实验。

ROADMAP 里原来那两个待测问题的处置：

- **(a) 冷页进前 5 的那些查询上，降权是改善还是恶化** —— **测了，都不是。**15 条查询
  的前 5 被重排，3 条的目标名次移动了一格，Recall@5 一动不动。
- **(b) 阈值该是绝对分数还是按面数归一化** —— **仍然没测，而且优先级应该降低。**归一
  化能让阀门在单面档里正确工作，但由 (a) 可知，正确工作的收益在这个库上是零。这是一
  个正确性问题，不是一个质量问题，别按质量问题的优先级排。

## 7. 边界

- **一个库，一批查询。** 一个冷层大得多的库——比如导入过一批已经死掉的旧书签——完全
  可能给出不同的结果。这里量到的是「在一个冷层只有 0.34% 的库上代价是零」，不是「这个
  缺陷无害」。
- **`cold_targets` 为空是查询集的性质，不是库的性质。** 查询集是从有正文的页面生成的，
  而冷页大多是死链。一个包含「找回那个已经打不开的旧页面」这类查询的查询集会直接
  推翻上面每一个数字。这大概是这份实验最需要被质疑的一点。
- **健康检查的覆盖率没有量。** 条件 3 的一半靠健康判定，而这个库上跑过多少次健康检查、
  覆盖了多少页，这份实验没查。冷层只有 8 页，可能有一部分原因是健康数据本身稀疏，而不
  是页面真的都还活着。

## 8. 复现

```bash
python scripts/decay_reach_probe.py \
  --db /path/to/library-w1-indexed.db \
  --queries eval/queries/w2w3-holdout.jsonl \
  --json eval/decay-reach.json \
  --now 1785649110
```

需要本地嵌入模型（要的是确定性，不是质量）：`--embed-path` 指向 bge-m3，
`--embed-dim 1024`。跑一次约 15 分钟，616 条查询 × 2 档。
