# 全端可靠性与体验修复

用户要求接手整个产品的排查、修复、体验打磨和回归，按模块提交 PR，通过验证后
逐个合并。定位为个人本地优先工具；提供的项目介绍仅作参考，入驻不是本轮目标。
原始基线为 main 的 v2.1.1 后续记录，源码从 `2977b3c` 开始检查。

## 验收方式

每个 PR 在同一份拟合并源码上运行 CI、收藏交互与截图、完整体验与 20 万条合成库、
Windows 打包安装。新的 Product quality gate 要求所有分发与交互检查均成功；
失败、取消、跳过均不能算通过。浏览器、构建、打包及安装不在本地执行。
证据只使用隔离合成数据；不接触真实浏览器资料，不把合成模型效果写成真实质量。

按真实用户路径检查首次启动、导入、搜索、目录、选择与管理、阅读、模型配置、
生成与任务恢复、聊天、备份同步、扩展、CLI/MCP、karakeep、原生桌面和分发。
每个问题需有源码依据、可复现条件和针对该条件的验证。排版与动效还需检查
云端渲染的明暗、中英、窄屏、短窗及键盘状态；技术通过不等于审美认可。

## 第一批 共享读取与索引

隔离检查先复现 6 项后端失败及 5 项客户端错误处理失败：

- 正文刷新只给 FTS 重建传入原标题与新正文，默认空字段使已经保存的 AI 标题、
  摘要、主题和标签丢失关键词可检索性。改为从实际保存的完整记录重建。
- 重导入空标题时，SQL 保留本地原标题，FTS 却写入空标题。导入与标签编辑复用
  同一重建入口，索引与持久记录保持一致。
- 详细阅读请求沿用结果摘要的约 200 字裁切。现在显式读取正文时同时返回完整
  已保存摘要，紧凑结果仍有长度边界。
- React 请求层在 HTTP HTML 错误页、204 空响应、损坏成功响应和网络断开时
  缺少稳定错误类型；Headers 对象中的额外头被对象展开丢掉。统一保留状态码、
  字段验证信息、配对头及调用方头，提供可以重试的错误信息。
- GET 请求增加 20 秒等待边界并释放取消监听；用户取消保留 AbortError 语义。
  写入和模型操作沿用服务端预算，客户端不自动重试这些操作。
- 收藏、完整体验、安装专项原来依赖分支约定或人工 dispatch；现在随每个 PR 的
  CI 自动执行，并汇总为明确质量门槛。扩展锁文件安装失败直接失败，避免回退安装
  未核验依赖后掩盖锁文件问题。

本批检查为 `tests/test_read_index_contracts.py` 和客户端独立运行的
`frontend/tests/unit/api.test.mjs`，后者从当前 TS 源码加载，使用真实 Response、
Headers 和取消对象；不启动浏览器，不执行完整前端构建。

修正后，本地新增后端 6 项、既有读取/重导入/标签等相关 15 项、客户端 8 项通过；
相关 Ruff、diff 与工作流 YAML/依赖检查通过。PR #55 的 [CI 43846203262](https://github.com/88lin/facetmark/actions/runs/43846203262)
18 个产品检查全部成功，包括四份 Python 系统/版本组合、完整浏览器、收藏、体验、
20 万条库、扩展、Docker、wheel、karakeep、真实 OpenCode 和 Windows 安装。
产物记录的测试合并提交为 `a54a285`，其树与修复 `aa7ec1c` 完全一致；收藏产物
163 份源码 SHA-256 均匹配。已检查安装版启动、阅读、原生链接与代表性导入画面。
PR #55 已于 2026-11-16 合并至 `main@4015dc3`；安装证据不代表发布了新版本。

## 第二批 导入与回执

在 `fix/import-workflow-2026-11-16` 接续导入改动，并在隔离数据上补复现：文件
导入未等待链接检查/模型写入，网站导入未出现在统一历史、立即停止遗漏记录、
重启后历史仍显示运行中。最初 5 项失败已修正。

- 批量粘贴最多 500 个网址，支持一行一个 URL 和可选 Tab 分隔标题。先预览
  新网址、已有收藏、本批重复和无效项，选择文件夹后只添加新内容，不抓取或调用 AI。
- 文件、本机来源和 URL 导入保存原子回执。丢失成功响应后的重试沿用原请求 ID，
  返回同一结果；不同内容复用 ID 或过期预览均拒绝写入。现有内容和浏览器原资料保留。
- 本机导入历史覆盖文件、本机来源、粘贴网址和网站扫描。列表分页、详情按需
  读取；网站扫描记录实时计数、成功、部分、停止和中断，服务重启标记未完成记录。
- 文件、URL 与网站控件互相反映忙碌状态，文件夹选择确实禁用；服务端同时保护
  处理任务、模型请求、聊天和链接检查。无效文件不再被误报为空导入成功。
- 修复历史详情关闭后卡在加载状态、详情失败却重试列表，以及网站导入完成后
  刷新失败丢失恢复入口。共享刷新原先吞掉错误，导入现在收到失败并保留成功回执，
  提供重新读取列表，避免再导入已经保存的内容。

本地新增 20 项导入契约检查通过；相关套件的 104 项导入/迁移/网站回归（含其中 16 项）、
75 份 TS/TSX 与 28 份 CSS 语法检查通过。限定到实际改动的 Impeccable 检查无发现。

本地依赖副本不能完成严格类型检查，未安装或重建本地依赖；云端从锁文件干净安装。

## 第三批 命名模型连接与设置恢复

补齐现有单套连接之外的本机命名连接。摘要/聊天和向量连接分别保存、命名、
重命名、移除和使用；命名操作不自动切换配置。密钥仅在本机原子保存，列表和
操作回执不返回密钥，也不进入书签导出或共享目录同步。保存响应丢失后的重试
保持原请求 ID 和配置快照，当前连接变更后也不会改写先前保存的记录。

已验证的连接保存独立验证证据，不会被多次未保存的模型测试挤掉。使用时复核
实际模型、端点、思考参数和 Agent 默认配置；仍一致时无需再调用模型。新的失败
测试会撤销对应命名连接的旧证明，损坏的本机文件会明确报错并保留原文件。
向量空间变更仍走现有备份与确认重建流程；活动任务和环境变量控制的字段不会被覆盖。

设置写入在同一锁内验证和保存，模型测试计入在途请求；界面增加即时提交锁，
避免 React 尚未提交忙碌状态时重复发送。调整对话并发数不再把摘要连接当作已修改。
保存成功与随后状态读取失败分开反馈，并保留成功回执及单独读取恢复入口。

本地先得到 11 项不存在命名连接入口的失败，再实现对应流程。新增 16 项档案与
在途模型检查；相关模型/连接/设置的 151 项回归及新增占用检查已通过。新界面与
云端场景语法检查通过，完整类型、渲染、键盘、失败恢复和安装仍待当前源码 Actions。
浏览器场景包含保存响应丢失、重复提交、重开与重命名、移除确认、保存后读取失败，
以及明暗/中英/320–1280px 长文本。收藏证据清单自动包含 Python 源码和前端测试，
新增功能不再依赖人工补齐指纹文件名。

首轮完整 CI 暴露 12 项摘要任务测试失败：旧测试仅注入指纹，没有成功测试结果，
与本批拒绝不完整连接证明的实际规则冲突。真实历史安装证明包含成功结果，既有
升级回归仍保留。测试改用真实保存证明入口记录合成成功结果，原任务、隐私、
原文保留及恢复断言不变；另补空结果和字符串真值不被当作成功的检查。

## 第四批 聊天回执、独立连接与阅读失败

创建对话原来只能由服务端分配 ID，成功响应丢失后前端无法读取原对话；消息的
去重还依赖会被“重试回答”覆盖的消息字段。本批保存原子创建回执与独立发送回执，
沿用客户端的冻结请求 ID、动作、语言、连接和收藏范围。删除后的创建回执保留
墓碑，迟到重试返回已删除；不同请求内容复用 ID 被拒绝。只读查询能确认某次
发送是否已被接受，另一窗口后续重试不会使原窗口永远卡在未确认状态。

每段对话可以独立选择已保存的聊天连接，后续问题保留选择，不改全局摘要连接。
缺失、未测试、验证撤销和环境变量锁定的连接明确拒绝；不会替换为其他模型。
命名连接拥有聊天专用客户端，回答结束后释放；没有可用向量时不初始化本机编码器。

输入事件立即保存草稿。本机只保留最近 24 项草稿、连接 ID、未确认操作与当前
收藏范围，过滤不支持或损坏的数据；不保存回答或密钥。创建期间输入的下一问
移交到真实对话 ID；服务端确认后只清理仍与已发送文本一致的草稿。刷新先读取
回执；继续发送是用户点击的显式操作，复用原快照，不因页面重开自动调用模型。
明确拒绝后，读取确认未接受即可恢复编辑连接；网络结果未知时保留原重试入口。

尚未配置模型时仍可写入并保留草稿，发送按实际连接状态禁用。初次与缓存对话
读取失败都有重读入口。停止、删除和历史分页使用即时锁或版本
校验；已删除对话的删除重试按成功收尾。状态区可以滚动，短窗的输入和停止按钮
继续可见。阅读页显示实际提取错误，区分没有正文和仍保留旧正文，并重试该篇收藏。

本地聊天、回执、再生成与命名连接的 68 项隔离回归，以及 4 项当前草稿模块检查
通过；TS/TSX、CSS 语法、相关 Ruff 与 diff 检查通过，限定实际界面的 Impeccable
静态检查无发现。浏览器新增真实服务端的创建/发送成功响应丢失、刷新只读恢复、
历史读失败、重复删除，以及独立连接、跨窗口回执、明暗/中英/窄屏/短窗和正文
错误入口检查。完整类型、构建、交互画面及安装仍等待本批当前源码 Actions；
不把前三批、静态检查或模拟连接画面作为本批已通过或真实模型质量的证明。

首轮第四批收藏专项发现四项初次发送检查失败。已读取失败日志和页面快照：
问题仍保留在输入框，没有创建对话或发送消息；旧场景将“输入框可编辑”作为
模型连接就绪的条件。允许未配置模型时写草稿后，该条件已经不代表能够发送。
场景现在等待实际发送按钮可用，原有消息、停止、恢复、请求次数和草稿断言保留；
另加连接状态延迟读取的真实服务端场景，确认提前输入及 Enter 不自动发送，
状态就绪后仍需显式发送且只发一次。新场景语法检查通过，运行结果以新提交
云端检查为准；首轮失败不记为全端通过。
