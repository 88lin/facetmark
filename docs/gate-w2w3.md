# 六个开关的判定：在没有参与产生它们的 616 条查询上

W1 的消融在 2,376 页真实书签上跑出四个结论，其中三个是"关掉它"。关掉一个机制是安全的
默认，但 W1 同时留下了一批**候选修复**——每一个都是"这个机制这样改就不会输了吧"的猜想，
每一个都实现好了、默认关着、**没有判过胜负**。

不判的理由不是懒。这些猜想全部是**看着那 479 条 W1 查询的结果想出来的**：`A_gatedctx`
之所以存在，是因为在那批查询上看到了 content −9.94pp 与 episodic +8.14pp 的分裂；
`C_notri` 之所以存在，是因为在那批查询上把 Facet 3 拆开看到 lex_tri 的贡献是 −0.42pp。
在同一批查询上给它们发奖，等于让假设自己批准自己。

所以这一轮做两件事，顺序很重要：先冻结一批全新查询和一套判定规则（`7f494c4`），
然后才跑档位。本文是判定结果。

---

## 1 判定对象：六个开关，两层基线

| 开关 | 它改的那一档 | 它声称什么 |
|---|---|---|
| `A_gatedctx` | `A_ctx` | 上下文乘子只在查询看起来带时间时开火 |
| `D_gated` | `D` | 同一个门控装在完整融合栈上 |
| `C_notri` | `C` | 删掉 Facet 3 的三元组那一半 |
| `C_lowlex` | `C` | 不删，把两个词面面的权重压到 0.3 / 0.2 |
| `C_abstain` | `C` | 一个面分不开自己的结果时就弃权（`abstain_margin=0.25`） |
| `C_max` | `C` | 加一个 CombMAX 项，系数 2.361 由 `guarantee_bonus` 解出而非挑出 |

每个开关判**两次**，因为"它做到了它声称的事"和"它该上线"是两个问题：

- **机制检验**：开关 vs **它修改的那一档**。回答"这个改法确实修好了它针对的那个毛病吗"。
- **上线检验**：开关 vs **`A`**，也就是当前默认档的检索核心。回答"能不能改默认"。

两层必须分开报，因为 C 家族在 W1 就比 A 低 5–6pp。一个 C 开关完全可能在机制上是真赢，
而距离上线还差着几个百分点——**只报机制检验就是在不说这件事**。

`A` 能代表默认档（`full` = content + graph + decay），依据是 W1 实测 `A -> A_graph`
为 +0.00pp 且**零条**不一致：图扩展从不碰排好的那一页，它只在第二组结果里多找到一些
目标。所以 `A` 与 `full` 的排序指标逐位相同。

## 2 查询集

`eval/queries/w2w3-holdout.jsonl`，**616 条**，写查询的模型是 `z-ai/glm-5.2`（W1 用的是
本地 Qwen2.5-3B-Instruct）。四个 seed 分块生成 634 条，合并去重后 616 条，`target_id`
全部可解析，覆盖 230 个不同目标页。分布：`q_content` 181、`q_vague` 211、
`q_episodic` 224。生成、去重规则与**五条已知偏差**写在 `eval/queries/README.md`，此处
只重复最要紧的一条：**库还是那个库**。这批查询解掉的是"提出假设与检验假设用同一批
查询"，不是"评测语料无偏"。

## 3 判定规则（在看到任何数字之前写好）

`scripts/switch_verdicts.py`。判"支持"要三条同时成立：

1. 点估计 > 0；
2. 配对自助法 CI95 的下界 > 0（10,000 次重采样，`bootstrap_ci`）；
3. McNemar 精确检验的 p 过 **Holm–Bonferroni** 校正后的门槛（α=0.05，两个家族各自校正，
   每个家族 m=6）。

两个门控档另加一条**分层**要求，因为它们的全部理由就是分层的：在上线检验里
`q_content` 的 CI 必须**含** 0（门控要求"内容型查询上什么都别发生"），且
`q_episodic` 的 CI 下界必须 **> 0**（"episodic 上的收益要留住"）。

每个比较同时报**这个 n 能看见多小的效应**（符号检验 80% 功效近似，
`detectable_pp_at_80pct_power`）。判"不支持"的意思是"在这个规模上没显示出帮助"，
不是"它有害"——这句话在看到结果之前就写好了。

## 5 机制检验（开关 vs 它修改的那一档）

| 比较 | ΔR@5 | CI95 | McNemar | p | Holm 门槛 | 这个 n 能看见 | 判定 |
|---|---|---|---|---|---|---|---|
| `A_ctx` → `A_gatedctx` | **+4.55pp** | [+2.76, +6.49] | 32 胜 / 4 负 | 1.9e-6 | 0.00833 | 2.73pp | **支持** |
| `C` → `C_notri` | **+4.54pp** | [+2.44, +6.66] | 37 胜 / 9 负 | 4.1e-5 | 0.0125 | 3.08pp | **支持** |
| `C` → `C_lowlex` | **+4.22pp** | [+1.46, +7.14] | 55 胜 / 29 负 | 0.00604 | 0.01667 | 4.17pp | **支持** |
| `C` → `C_max` | **+4.22pp** | [+2.60, +6.01] | 29 胜 / 3 负 | 2.6e-6 | 0.01 | 2.57pp | **支持** |
| `C` → `C_abstain` | +0.16pp | [+0.00, +0.49] | 1 胜 / 0 负 | 1.0 | 0.05 | 0.45pp | 不支持 |
| `D` → `D_gated` | −0.16pp | [−1.46, +1.14] | 7 胜 / 8 负 | 1.0 | 0.025 | 1.76pp | 不支持 |

四个开关做到了它们声称的事，两个没有：

- **`C_abstain` 几乎是个空操作。** 616 条查询里只有 **1 条**结果变了。`abstain_margin=0.25`
  的意思是"一个面的最高分与最低分差不到自己分数范围的四分之一时就弃权"，而 RRF 的分数
  分布几乎从不这么平——这个阈值在真实数据上基本不触发。它可看见的效应低到 0.45pp，
  也就是说这不是"功效不够"，是**真的什么都没发生**。
- **`D_gated` 与 `D` 无法区分。** 7 胜 8 负。原因看得见：`D` 的 `q_episodic` R@5 已经是
  0.3214，而 `D_gated` 也是 0.3214——在完整融合栈上，上下文乘子的作用已经被别的面
  淹没了，门不门控都一样。**门控是对 `A` 有用，不是普遍有用。**

`C_lowlex` 的 55 胜 29 负值得留意：它的净收益和 `C_notri`、`C_max` 差不多（+4.2 vs
+4.5pp），但**扰动大得多**（84 条不一致 vs 46 和 32）。压权重会把很多页的位置一起挪动，
其中近三分之一挪坏了。三个赢家里它是最粗的那把工具。

## 6 上线检验（开关 vs `A`）

| 比较 | ΔR@5 | CI95 | McNemar | p | Holm 门槛 | 这个 n 能看见 | 判定 |
|---|---|---|---|---|---|---|---|
| `A` → **`A_gatedctx`** | **+3.09pp** | **[+1.79, +4.55]** | **19 胜 / 0 负** | **3.8e-6** | 0.00833 | 1.98pp | **支持** |
| `A` → `C_notri` | −3.41pp | [−6.66, −0.32] | 41 胜 / 62 负 | 0.04823 | 0.05 | 4.62pp | 不支持 |
| `A` → `C_lowlex` | −3.73pp | [−6.98, −0.49] | 40 胜 / 63 负 | 0.02968 | 0.01667 | 4.62pp | 不支持 |
| `A` → `C_max` | −3.73pp | [−7.14, −0.32] | 48 胜 / 71 负 | 0.04327 | 0.025 | 4.96pp | 不支持 |
| `A` → `D_gated` | −5.84pp | [−9.58, −2.27] | 47 胜 / 83 负 | 0.00202 | 0.0125 | 5.19pp | 不支持 |
| `A` → `C_abstain` | −7.79pp | [−11.53, −4.22] | 44 胜 / 92 负 | 5.0e-5 | 0.01 | 5.30pp | 不支持 |

**三个 C 家族的赢家全部止步于此。** 它们每一个都真的修好了 C 的一部分（+4.2 到 +4.5pp），
而 C 离 A 有 8pp——修好一部分之后还差 3.4 到 3.7pp。W1 的结论没有被推翻：**在这个库上，
把任何东西融进内容向量都还是不如只用内容向量。** 这三个开关继续留着、继续默认关闭，
它们的价值是把"融合为什么输"这件事说清楚了，不是把它救回来了。

（Holm 的步降在 `C_lowlex`（p=0.02968 > 0.01667）处停下，因此 `C_max` 与 `C_notri`
即使各自的 p 小于自己那一格门槛也不算拒绝——这是步降法的定义，不是笔误。它们的点估计
本来就是负的，任何一条都足以判不支持。）

### `A_gatedctx` 过了，包括它必须过的分层前置条件

| 分层 | n | ΔR@5 vs `A` | CI95 | McNemar | 预注册要求 | 结果 |
|---|---|---|---|---|---|---|
| `q_content` | 181 | +0.00pp | [0.00, 0.00] | 0 胜 / 0 负 | CI 必须**含** 0 | 通过 |
| `q_vague` | 211 | +0.00pp | [0.00, 0.00] | 0 胜 / 0 负 | （无要求） | — |
| `q_episodic` | 224 | **+8.48pp** | **[+4.91, +12.05]** | 19 胜 / 0 负 | CI 下界 **> 0** | 通过 |

**19 胜 0 负、全部来自 `q_episodic`。** 这不是"平均起来变好了"，是**没有一条查询变差**。
门控关掉的那部分流水线在非 episodic 查询上逐位等于 `A`，所以那 392 条的排序**完全没
被碰过**；而在 224 条 episodic 查询里，乘子帮了 19 条、害了 0 条。

W1 那两个数字的下场：**content 的 −9.94pp 没了（+0.00pp），episodic 的 +8.14pp 留住了
（+8.48pp）**。这正是当初提出门控时希望发生的事，而这次它是在没有参与提出它的查询上
发生的。

**据此改默认**：`FULL` 从 `Config("full", {"content"}, graph=True, decay=True)` 改成
再加 `context=True, context_gate=True`。挂在这个改动上的数字就是上面那一行
（+3.09pp，CI95 [+1.79, +4.55]，19 胜 0 负，p=3.8e-6）。

## 7 这批测量**没有**检验到的事

**(a) 门控的精确率没有被检验，而它是这次收益的前提。** `A_gatedctx` 的收益 =
乘子作用在**门控挑出的那批查询**上的收益。门控挑得准不准是另一件事，而这批查询几乎无法
检验它：生成器造 `q_episodic` 时，时间短语由 Python 构造并**用产品自己的 `classify()`
校验**，解析不出就丢弃。所以"门控触发集合 ≈ `q_episodic` 标签"里有一大半是构造出来的。

实测（`scripts/gate_firing.py`，`eval/gate-firing-w2w3.json`，时钟钉在库的
`meta.created_at`）：

| 类型 | n | 触发 | 触发率 |
|---|---|---|---|
| `q_episodic` | 224 | 224 | 100%（构造，不算证据） |
| `q_content` | 181 | 1 | **0.55%** |
| `q_vague` | 211 | 0 | **0%** |

有意义的是反方向：content 与 vague **从来没有被筛过时间词**，所以它们上面的 0.55% 与 0%
是真实测量。唯一那条误触发是 **"kids reading for fun declined half since 2012"**——年份
属于**内容**，不是"我什么时候存的"，正是这个机制该有的失败形态（它没有把这条查询挤出
前 5，所以 `q_content` 那一格才是 0 胜 0 负）。

但 0.55% 这个数字不能外推。真实用户会问"2015 年那批论文"、"去年发布的 Rust 教程"——
**内容里带年份的查询在真实书签库里远比 181 条造出来的内容型查询更常见**，每一条都要付
`A_ctx` 那份 −9.94pp 的代价。门控要真正被判精确率，需要一批**专门写来带时间词但问的是
内容**的查询。**这件事没做，默认值是在这个已知空白上改的。**

**(b) 四个分块不同分布。** 四块的丢弃率在漂移（`q_vague` 0.0635 → 0.127 → 0.2222 →
0.1429，端点 `JSONDecodeError` 3 → 4 → 13 → 6），所以 616 条不是同分布抽样。每行带
`chunk` 字段，可事后分层核查。

**(c) 库还是那个库。** 2,376 页里 21% 没有正文、部分页面中文标题配英文正文。这些库层面
的偏差 W1 和 W2 两批查询**都有**，换查询集解不掉。

**(d) `A_gatedctx` 的 R@1 也涨了**（0.4237 → 0.4367），但 R@1 不在预注册的判据里，
这里只作为记录，不作为结论。

**(e) 没有重跑 `D+exp` 的图扩展缺陷修复。** `fc0444f` 修好了扩展代码，但 `D` 与 `D_gated`
的 `R@5+exp`（0.5536 / 0.5503）仍来自修复前后未重跑的口径，视为**下界**。

## 8 复现

```bash
# 十档，616 条查询，约 39 分钟（1 CPU，本地 bge-m3）
python -m facetmark.cli eval --no-build --db library.db \
  --queries eval/queries/w2w3-holdout.jsonl \
  --rungs A,A_ctx,A_gatedctx,C,C_notri,C_lowlex,C_abstain,C_max,D,D_gated \
  --bootstrap 1000 --concurrency 1 --out eval_switches.json

# 预注册判定（CI 在这里用 10,000 次重采样重算）
python scripts/switch_verdicts.py --report eval_switches.json \
  --out eval/switch-verdicts.json --bootstrap 10000

# 门控触发面诊断
python scripts/gate_firing.py --queries eval/queries/w2w3-holdout.jsonl \
  --db library.db --out eval/gate-firing-w2w3.json
```

判定产物落在 `eval/switch-verdicts.json`；含逐条 rank 的完整报告是 628 KB，不入库，
但上面第一条命令是确定性的（`BOOTSTRAP_SEED` 固定），重跑得到同样的数字。
