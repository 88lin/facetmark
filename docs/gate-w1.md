# W1 决策闸门：A–E 消融结果

**结论先说：三条预注册判据全部未通过，而且失败的方向和预期相反。**

不是「加了机制但提升不够」，是**加了机制反而更差**。最简单的那一档——单个内容向量，
没有词面、没有意图面、没有上下文、没有图、没有重排——在总体 Recall@5、Recall@1 和
MRR@10 三个指标上都是最好的，而且快 3.5 倍。

这份文档记录判据、数字、判定，以及为什么我认为这不是「理念错了」而是
「融合方式错了」——以及为什么这个区分本身需要下一轮实验才能确认，不能在这里下定论。

## 4. 真正的发现：融合在稀释一个本来就很强的检索器

预注册的判据结构里藏着一个假设：**A 是个弱基线**。数据说不是。

A 的 q_content Recall@5 是 **95.9%**。加上两个词面之后掉到 91.2%，
McNemar 输 56 赢 30。这不是噪声，是显著的回归。

原因不难猜。RRF 的融合权重是平的：

```python
DEFAULT_FACET_WEIGHTS = {"content": 1.0, "intent": 1.0, "lex_seg": 1.0, "lex_tri": 0.7}
```

每个面无条件交回 `candidates_per_facet = 50` 条。当内容面已经把正确答案排在第 1
位时，它贡献 `1/(60+1) = 0.0164`；而两个词面各自把某个只是共享了几个词的文档排在
第 1 位，合起来贡献 `1/61 + 0.7/61 = 0.0279`。**一个词面上的巧合可以盖过一个向量面上的
确信。** RRF 的设计前提是被融合的检索器质量相当；这里不相当。

这不是推测。把逐条判决拉出来数（不调任何旋钮，纯计数）：

| 观察 | 数值 |
|---|---|
| A 把目标排在**第 1 位**的查询 | 242 / 479 |
| 其中 B 仍然保持第 1 位 | 173（**丢了 69 条，28.5%**） |
| 其中 D 仍然保持第 1 位 | 158（**丢了 84 条，34.7%**） |
| A 命中 top-5 而 B 丢掉的 | 56 条 |
| ——其中在 A 里本来排第 1 的 | **27 条** |
| ——其中被 B 挤出 top-10 的 | **25 条** |
| B 命中而 A 没命中的 | 30 条 |

丢失集按类型：q_vague 22 / q_episodic 21 / q_content 13。**恰恰是词面最没有信息量的
那两类查询受害最重**——模糊查询本来就没有几个有区分度的词，词面交回来的就是噪声。

几个具体的（A 名次 → B 名次）：

```
[q_content] 1 -> 未命中   如何查看浏览器历史记录
[q_vague]   1 -> 6        科学家的创新周期
[q_vague]   1 -> 未命中   unique identifier system
[q_content] 1 -> 6        apple的设计转变
```

第一条特别值得看：一个中文查询，内容向量稳稳排第 1，加上词面之后直接掉出前十。
中文在 `lex_seg` 上的切分质量本来就差，切出来的碎片匹配到一堆无关页面，
每一个都往融合分里加一票。

需要说清楚的是：**A 不是朴素基线**。内容向量嵌的是
`标题 + 摘要 + 主题·实体 + 正文前后各 1000 字`，摘要和主题都是 3B 模型 enrich 出来的。
也就是说 A 已经吃掉了 enrichment 的大部分收益，剩下三个面要在此之上再加价值，
门槛比设计时假设的高得多。

## 5. 唯一守住的地方：情景查询

q_episodic 是整个项目的立项理由——「我去年存过一篇讲 X 的东西」。这一类上：

- A = 27.9%
- D = 34.3%（+6.4pp）
- D 带图扩展 = **40.7%（+12.8pp）**

这是全表唯一一处复杂度换来了实打实的收益。而且注意 C→D 在主指标上只有 +0.41pp
（p=0.80），却在 `recall@5+exp` 上有 +3.3pp（总体）/ +9.9pp（episodic）——**D 相对 C 的
价值几乎全部落在主指标不看的那个列表里。**

这里有一个必须写明的偏差来源：本次评测跑的代码带着一个图扩展缺陷（排除集用了整个
融合候选池而不是展示给用户的命中，详见 CHANGELOG）。缺陷会系统性地删掉**最好的**
那批邻居——恰恰是向量面也检索到的那些。所以 40.7% 是**下界**，不是真值。

另一处偏差：C→D 的 `graph` 开关对 `hits` 排序没有任何影响，只填充 `expanded`。
因此**「D−C 在 q_episodic 上 ≥ +10pp」这条判据，实际检验的只是上下文乘子
（窗口 0.50 / 会话 0.25 / 文件夹 0.15）一个信号，不是图。** 判据的措辞在设计时
就没有把这两者分开，这是判据本身的缺陷，记录在此。

## 6. 内容向量的正确性（前置校验）

闸门跑之前先证明检索器读到的向量确实是它该读的向量。抽 40 篇重新嵌入，与库里
存的比对：

| 对照 | 结果 |
|---|---|
| stored vs 当前 enriched 文本 | min 1.0000 / median 1.0000 / 低于 0.999 的：**0** |
| stored vs 仅标题 | max 0.6911 / median 0.6412 / 等于 1.0 的：**0** |

修复前同一个校验：`vs_enriched_text` median **0.6854**、`vs_title_only` **12/12 等于 1.0**
——即库里存的全部是 enrich 之前的仅标题向量。这个缺陷（`embed_content(force=False)`
只看「有没有向量」不看「向量是不是过期了」）已修，并加了 `vec_content_meta` 表记录
每条向量的输入指纹。

语义边距离上限按**预注册规则**（随机文档对距离分布的第 1 百分位，四舍五入两位小数）
重算，得 **0.93**（旧的仅标题向量上是 0.96，代码里写死的默认值是 0.60）。重建后：

| | 修复前 | 修复后 |
|---|---|---|
| semantic 边数 | 430 | **7,014** |
| 有语义邻居的文档 | 113 / 2,376 = 4.8% | **1,887 / 2,376 = 79.4%** |

0.60 这个拍脑袋的默认值让语义边覆盖了不到 5% 的库。这也是为什么 §5 里图扩展的
收益此前完全看不出来。

## 8. 按预案的后续

设计报告写好的两轮预案，现在生效：

1. **抽 50 篇人工读意图抽取输出**，判断 F2 的失败是 3B 模型不够，还是「让模型预写
   用户可能怎么问」这个理念本身不成立。
2. **试查询侧意图改写**（`search/understand.py` 已有钩子）。

但这次的数据把优先级改了。在跑这两轮之前，更该先做的是第三件事：

3. **修融合权重。** A→B 的 −5.43pp 是全表最大的单步回归，而它的成因（平权 RRF 让
   弱面覆盖强面）是可检验、可修的：给词面加低权重，或者只在内容面**不自信**时才让
   词面参与。这件事必须用**新的查询集**做，不能用这 479 条——那 479 条已经看过一次
   数据了，再拿来调旋钮就是在自己的考卷上改分。

**默认配置的处置。** 预案原文写的是「不通过则默认配置降级为 B」。数据否决了这个预案：
B 是全表最差的一档。按实测，默认应当降为 **A**，把 B/C/D/E 保留为实验性开关。
这一条改动的依据是本表，不是事后偏好。
