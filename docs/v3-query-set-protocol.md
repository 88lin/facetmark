# v3 查询集构造协议

**这份文件写在生成任何一条 v3 查询之前，也写在用这批查询跑任何一档之前。** 目标池的
定义、各池能出哪些查询类型、校验器、规模与停止规则都在这里定死，先后可从 `git log`
外部核对。

---

## 0 为什么现在写这个

ROADMAP 上排着四笔账，它们共同的前置条件是一批新查询集：

1. **冷层条件 3 的窄化**（1.6.0 量出现行定义要付 ΔRecall@5 = −1.4610pp）。两个候选改法
   ——(a) 从 `DEAD_VERDICTS` 去掉 `drifted`、(b) 只在 `char_count < 200` 时降权——都是
   **看了现有 616 条查询的失败案例之后想出来的**。在同一批上评估等于报训练集分数。
2. **`gate_v3`**：把 `time:relative` 也收窄。`gate_v2` 在 361 条探针上证明了对裸年份
   有效，剩下的 −10.52pp 全部来自相对时间词。但那 361 条已经被用来在 v1 和 v2 之间
   做过选择，再用它们选 v3 就是循环。v3 需要自己的预注册和自己的探针集。
3. **门控漏响率一次都没量过。** 整个预注册实验只测了误响的一面；真实库演示里
   「上次存的那个签到脚本」压根没被判成情景查询（`docs/real-library-demo.md`）。
4. **W2 融合规则与 W3 判据的重写**都要求在「没有参与提出假设的查询」上复核。

现有 1,095 条查询（W1 的 479 + W2/W3 的 616）有一个共同的结构性盲区：**全部生成自
有正文的页面**（W2/W3 那批虽然引入了 `--bodyless-share`，但 bodyless 池只出
`q_vague` / `q_episodic`，且不含任何死链信息）。于是「找那个已经打不开的旧页面」
这类意图一条都没有，冷层与目标集的交集只有 8 个目标、19 条查询——任何关于「降权
死链会不会伤到答案」的测量都是虚的。

v3 查询集要一次性补上三个缺口：**死链目标**、**只有标题可用的目标**（W2/W3 已有，
v3 保留并显式分层）、**确实在找某次保存动作却不含任何门控词表的查询**。

明确**不**做的事：

- 不判定任何检索档位。这批查询生成、冻结之后，才轮到各个实验各自写自己的预注册。
- 不改任何默认值。生成器只加新池和新类型，现有池的口径一个字不动。
- 不 reopen W1 / W2 / W3 的结论。v3 是它们的下游仪器，不是它们的上诉法院。

## 1 这份协议要回答的问题

> 能不能构造一批查询，使得 (i) 它**故意**包含死链目标和无正文目标，(ii) 它包含一类
> 确实在找保存动作、却不含年份也不含现有门控词表的查询，(iii) 它的构造规则在任何
> 实验看到它之前全部冻结？

这是一个**构造协议**，不是判定协议。它交付的是仪器，不是读数。

## 2 目标池

库：`library-w1-indexed.db`（与 W1、W2/W3、门控精确率实验同一份快照，md5
`5c3249a2b1f510a6d68af13c0763d8c3`）。三个池，互不重叠：

### 池 1：正文池（body）

与现有生成器完全同口径：`indexable = 1`、`body_hash IS NOT NULL`、
`char_count >= --min-chars`（默认 300）。出 `q_content` / `q_vague` / `q_episodic`。

### 池 2：无正文池（bodyless）

与现有生成器完全同口径：`coalesce(char_count, 0) = 0`，且标题加地址词至少含两个
内容词（低于此线模型只能编造，跳过并计数）。出 `q_vague` / `q_episodic`，**不出
`q_content`**——没人读过这页，编一个内容查询就是往查询集里塞这页可能从未含有的词。

### 池 3：死链池（dead）

**v3 新增。** 入选条件是这条书签在 1.6.0 那次全库健康检查里被判 `gone` 或
`drifted`（`DEAD_VERDICTS` 的两个成员；`soft_gone` 在该次检查中出现 0 次）。判定
数据来自 `eval/cold-census.json` 的 `snapshots.checked.cold_breakdown`，共 **65 个
目标**：gone 37 + drifted 28。

死链池按**可服务性**分两层，这是整个池的要害：

| 层 | 定义 | 数量 | 能出的类型 |
|---|---|---|---|
| 可服务（servable） | 索引时抓到的正文 `char_count >= 200` | 27 | `q_content` / `q_vague` / `q_episodic` |
| 不可服务（unservable） | `char_count < 200`（含 0） | 38 | `q_vague` / `q_episodic` |

**可服务死链可以出 `q_content`，这是与无正文池的唯一区别，也是刻意设计。** 冷层
条件 3 的 bug 恰恰是「URL 现在死了」被当成「存下来的副本没用了」：这 27 页的正文
**还在索引里**，用户也完全可能记得它讲了什么。不给它们出 `q_content`，v3 就测不到
「降权死链伤到正确答案」这条最主要的伤害路径——1.6.0 那 8 个受损目标里 4 个正是
这种情况。不可服务层与无正文池同理，不出 `q_content`。

**死链判定数据的三个注意点（写在这里，下游报告必须复述）：**

1. **单次观察。** `health_gone_confirm_days = 7` 的设计意图是「一次 404 不算死，要
   连续两次、间隔 7 天以上」。1.6.0 只跑了一遍，所以这 65 个目标严格来说没有满足
   产品自己的确认条件。v3 把它们当死链用，是因为**测量需要**一批死链目标，而不是
   因为产品已经确认它们死了。
2. **local-only 上界。** 那次检查是 `health_enable_external=False` 跑的，按
   `synth.py` 的规则顺序这是最偏向判死的配置（rule 1 外部正面观察 → `restricted`
   先于 rule 2 本地 404 → `gone`）。所以 65 是死链池的**上界**，开外部证据只会更小。
3. **verdict 会随时间变。** 冻结的查询集记录的是「构造那一刻的判定」。下游实验引用
   v3 时必须引用这个时钟（`cold-census.json` 的 `clock = 1785649110`），不得用「现在
   又活了」来翻案——那正是衰减层要处理的现实，不是查询集的缺陷。

### 抽样与配额

- 正文池与无正文池的规模由 `--n` 与 `--bodyless-share` 决定，与 W2/W3 同机制
  （默认取库自己的比例，W1 库上约 22.5%）。
- 死链池的规模由新参数 `--dead-share` 决定，**默认 0.10**（目标的 10%）。65 个目标
  全池只有这么多，按保存年份分层抽样（与主生成器同一函数），可服务层与不可服务层
  按比例进入。死链池目标数超过 65 时取全池并明说。
- 三个池在 `bookmark.id` 上互斥：死链池从健康表取，正文/无正文池的 SQL 不变——
  一个 id 同时满足时（可服务死链有正文），**死链池优先**，从正文池候选里剔除，
  避免同一目标以两种身份各出一组查询。

## 3 查询类型

三个现有类型不变。新增第四个：

### `q_save_action`（保存动作型）

用户记得的是**「我存过」这个动作本身**，而不是页面讲了什么、也不记得什么时候存的。
这是门控漏响率的探针，也是真实库演示里「上次存的那个签到脚本」那一类。

**构造规则（要害全在这里）：**

1. 查询必须表达「找的是自己保存过的东西」这个意图——「我存过的那个」「之前收藏的」
   「the one I saved」「in my bookmarks」。
2. **禁止出现门控词表里的任何触发词**，否则它测的就不是漏响：
   - 年份（`_ABS_YEAR` 的 1980–2049）、`n_ago`（三个月前 / two weeks ago）、
     `time:relative` 全部 12 条（今天/昨天/…/最近/今年/去年/前年 及英文对应）；
   - `_VAGUE_EPISODIC` 全部 13 条（那阵子/当时/刚开始/…/back when/…）；
   - `_SAVE_ACTION` 里**已被门控使用的**词（保存/收藏/存的/存过/存了/书签/上次/那天/
     我存/saved/bookmark/bookmarked/i kept/my bookmarks）。
3. 第 2 条与第 1 条直接冲突——这正是漏响的机制：用户表达保存意图的自然词汇，大半
   已经被门控征用了。所以 `q_save_action` 的提示词要求模型用**未被征用的**说法表达
   同一个意图（「我存过的那个」「之前收起来的」「the one I put away」「from my
   collection」），校验器逐条对照三张词表拒绝。
4. **`classify()` 不过滤。** 门控开不开火是**结果变量**，不是入选条件——与门控精确率
   协议 §2 的立场完全一致。那里 `classify()` 是被测对象，这里也是。
5. 每个目标最多出一条 `q_save_action`，且与同一目标的其他类型并存（合并去重的单位
   仍是 `(target, qtype)`）。

**规模**：由新参数 `--save-action-share` 决定，**默认 0.15**（目标的 15%），从三个池
的并集里按保存年份分层抽取——死链目标同样可以是「我存过的那个」的答案，而且这是
冷层窄化实验最想看的交叉格。

### 各池 × 类型矩阵（冻结）

| | q_content | q_vague | q_episodic | q_save_action |
|---|---|---|---|---|
| 正文池 | ✓ | ✓ | ✓ | ✓ |
| 无正文池 | — | ✓ | ✓ | ✓ |
| 死链·可服务 | ✓ | ✓ | ✓ | ✓ |
| 死链·不可服务 | — | ✓ | ✓ | ✓ |

## 4 校验器

三个现有类型的校验器全部沿用，一个字不改。新增两条：

1. **`check_save_action`**：先过 `check_shape` 的全部门槛（长度、CJK 比例、关键词串、
   示例鹦鹉学舌）；然后逐条对照 §3.2 的三张词表，命中即拒，理由喂回模型重试（最多
   `--retries` 次，之后丢弃并计入丢弃率）。**不**要求查询与页面内容有任何重叠——
   用户记得的是动作，不是内容；但也**不**禁止内容词，只要它不带门控触发词。
2. **死链池的材料约束**：可服务死链用与正文池相同的提示词（模型看得到正文）；不可
   服务死链用无正文池的提示词变体，材料只有标题、地址词、文件夹、同会话邻居，外加
   一行健康判定（`gone` / `drifted`）——这是一个人能真实掌握的全部信息。提示词
   **不得**暗示「这页现在打不开」，因为用户存的时候它是活的，查询里出现「那个打不
   开的页面」会把死链身份泄给词面面。

## 5 规模与停止规则

- 4 个种子块（与 W2/W3 同惯例），每块 `--n 64 --concurrency 8`，合计 256 个目标；
  按 `--dead-share 0.10 --save-action-share 0.15` 期望产出 **600–650 条**查询
  （与 W2/W3 的 616 同一量级，配对自助的统计功效可比）。
- 接受 **≥ 500 条**即冻结。实际接受数、各类型丢弃率、死链池实际占比一并报告。
- **不因为分布不好看而补生成，也不因为好看而提前收工。** 接受数低于 500 同样冻结，
  把功效不足写在分布报告里。

## 7 这份协议测不到什么

- **死链判定的时效。** 见 §2 的三个注意点。v3 记录的是构造时刻的判定，不是永恒真理。
- **真实用户的保存动作词。** `q_save_action` 的「未被征用的说法」是模型写的，未必是
   人会打的那一句。它给出的是漏响率的**下界**：连这些词都不触发，真实词汇只会更多。
- **库还是那个库。** 2,376 条公开语料快照，不是任何人的真实书签。
