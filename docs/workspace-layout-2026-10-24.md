## Issue #52 · 工作台失败后立即重试

旧逻辑用 `child.is_none()` 决定重试，`kill()` 消耗句柄后立即视为可重启，却没有等待
实际 `Terminated`。因此旧进程仍持有 `.desktop.lock` 时，新 sidecar 可能验证并复用
那个将要退出的兼容服务。旧安装测试在按 Enter 前先等 PID 退出，遗漏了竞态。

当前用 `SidecarGate` 管理 Idle / Running / Stopping 和启动 generation。失败先进入
Stopping，发 stdin stop，必要时 kill；只有当前 generation 的 Terminated 释放重试。
重试在后台等待，UI 保持 connecting / disabled；超时仍关闭重启闸门，保留恢复提示。
旧退出事件和迟到 stop worker 不能操作新 generation。启动超时与 ready 共同争用一次
starting 标记，迟到 ready 不能再打开即将关闭的服务。

Rust 回归包含原 child-empty 负对照、实际退出前持续禁止 begin、陈旧退出和等待超时。
安装测试在严格的 hosted-CI 条件下控制失败服务的退出时机，真实按 Enter 时旧 PID
和实例锁仍活着；断言没有新 spawn，再释放退出，核对新 owned 服务、不同 PID、
实际 Terminated、12 次连续 health 成功。控制退出时机是测试注入，进程、锁、
原生窗口、Enter 和恢复服务均为真实安装运行。

本节说明源码和待验方法；尚未关闭 issue 或宣称安装修复已验证。

云端将运行完整页面、1440/1280/1024 密度、窄屏、长中英标题 / 多种摘要、
阅读切换 / 尾段 / 返回顶部、设置标签 / 下拉 / 草稿 / 焦点、
文件夹 / 表单 / 关闭 / 减少动态效果、原生启动及真正安装后的托盘操作。
HTML 合成 bridge 截图与安装后的原生 API 证据分别标注。

它仍操作真实原生窗口，但不会宣称完成了真实右键打开。
