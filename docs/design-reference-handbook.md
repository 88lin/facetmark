# 软件与网站设计参考手册

版本：0.1 · 更新日期：2026-10-22 · 状态：持续收集与筛选

这份手册把参考资料整理成可用于设计、开发和评审的说明。它随资料积累更新，既服务于 Facetmark，也可整份复制到其他软件或网站项目中使用。

正文保存通用方法、具体交互机制、来源和使用边界；项目选择单独记录。参考被收录，表示其中有值得研究的做法，不表示用户已经认可整站风格、批准某个组件，或要求安装对应依赖。

## 1. 如何使用与继续补充

开始一个项目时，先确定用户任务、内容规模、平台与品牌，再从本手册选择适用条目。产品工作区、展示型网站、阅读页面可以采用不同的表达强度；这里不统一规定配色、圆角、材质或动效数量。

后续收到资料时，按以下顺序处理：

1. 读取原始页面，定位具体组件、交互或版式，避免只收藏首页链接。
2. 写清它解决什么问题、通过什么机制实现，以及适用和不适用的场景。
3. 有公开源码时检查实际实现、数据来源、依赖和许可。区分原作者作品、第三方重写和本站原创。
4. 将有价值的内容并入已有条目，或新增一个可检索的条目；重复资料补充来源，不反复堆叠相同原则。
5. 项目实际使用后，补充改造方式、运行验证和用户反馈。被否定的方案保留否定原因，退出该项目的当前设计依据。

每条资料分别记录两类状态：

| 维度 | 可用标记 | 含义 |
| --- | --- | --- |
| 证据 | 页面已读 / 源码已核 / 运行已验 | 分别说明读到了什么、代码能证明什么、实际操作验证了什么 |
| 采用 | 参考候选 / 项目已采用 / 用户已认可 / 暂不采用 | 采用决定属于具体项目，不自动推广到其他项目 |

本版已读取三个网站的公开内容，并抽查指定源码。没有运行这些网站的浏览器交互，也没有核实动画体感、帧率、所有响应式状态或完整无障碍表现。下面的设计判断与待验证项不等同于运行结论。

## 3. 可跨项目复用的设计方法

### P01：先写用户任务，再选视觉效果

选择一个效果前，写成一句具体需求，例如：“用户完成复制后，需要立即知道复制成功，同时继续阅读原内容。”随后决定反馈的位置、持续时间、静态状态和失败处理。

动效可以提供确认、方向、层级、物体关系和情绪表达。工作界面优先保证连续操作；作品集、品牌页和活动页可以通过更充分的材质与运动建立记忆点。不要把一个组件展示页的表现强度默认应用到整个产品。

参考：S01 的图标反馈、S02 的交互说明方式、S03 的组件用途说明。此条是综合设计建议。

### P02：让用户看得见变化从哪里发生

菜单从触发器所在位置展开；预览与对应条目保持可追踪关系；前进、返回和面板切换使用一致的方向。动画期间尽量保留可识别的对象，帮助用户理解位置和状态变化。

Cantrip 的“从按钮长出的菜单”使用触发器所在角作为 `transform-origin`，打开约 180ms、关闭约 100ms；指针悬停时高亮可以移动，方向键连续导航时高亮直接到位。

可借用的是空间关系与输入方式的区别。上述时长是示例参数，不是所有产品的标准。正式菜单还要处理窗口边缘、定位翻转、Esc、焦点返回和关闭期间停止交互。

来源：[S02 · 菜单说明](https://cantrip.cn/i/origin-menu) / [示例源码](https://cantrip.cn/code/origin-menu)。

### P03：用真实状态驱动反馈，保留稳定的操作位置

进度、成功、失败和重试放在发生操作的对象附近。状态变化可以改变局部图标、文字或进度线，避免为每一步新增一整块区域。

适合上传、导入、保存、连接测试和后台任务。未知进度使用“处理中”等真实状态；只有后端确认后才能显示成功。重试继续作用于原对象，任务范围不随动画或页面切换改变。

减少动态效果时，应缩减运动、保留真实状态。动画播完、延时结束或滚出视口都不能代替业务完成。

来源：S01 · Check 图标；[S02 · 迷你上传列表](https://cantrip.cn/i/mini-upload-list)。后者有重要的演示逻辑边界，见第 4 节。

### P04：在紧凑导航里同时保留当前层与来路

“渐进树导航”每次展示当前一层，祖先路径保留在上方并可返回。它适合窄空间内的层级选择，例如目录选择器、设置分类或移动端导航。

应用到真实目录时，还需保留搜索、完整路径、同名节点辨别、加载和失败状态。允许选择父目录时，“进入下一级”和“选择此目录”应有清楚的区分。频繁比较多个分支的任务可能更适合展开式树或分栏浏览。

示例的固定坐标、少量节点和一次性构建不能直接扩展成大型目录。具体布局应由窗口空间、文字长度与数据规模决定。

来源：[S02 · 渐进树导航](https://cantrip.cn/i/progressive-tree-nav) / [示例源码](https://cantrip.cn/code/progressive-tree-nav)。

### P05：渐进展示操作，同时保持可发现与可访问

将高频操作留在当前视线内，低频操作收进有名称的菜单或次级面板。批量操作随选择状态出现；复杂设置按任务分组，必要时分步完成。

useLayouts 的 Dynamic Toolbar 按实际内容测量容器宽度，Multi Step Form 测量内容高度并按前进、返回方向切换。可学习的是内容和容器协同变化，而不是固定某个胶囊外形。

实现时，隐藏面板应退出键盘访问；重新展开后仍能找到正确焦点。测量需要覆盖中文、长标签、缩放与错误提示。分步表单在返回时保留输入，校验失败能定位具体字段，不能让流程状态只存在于动画组件内部。

来源：S03 · Dynamic Toolbar、Multi Step Form。对应源码边界见第 4 节。

### P06：通知留出阅读时间，长期状态有固定入口

短通知可以堆叠，展开阅读或操作时暂停倒计时，再按剩余时间继续。快速连续到达的通知应从当前位置衔接，不反复回到初始位置。

正式实现还要支持键盘焦点、触屏、关闭按钮和适当的状态播报。需要用户处理的失败、长时间任务与历史记录应留在任务区或原操作附近；通知是补充入口。

Cantrip 的示例最多露出 3 条通知，用 CSS transition 处理堆叠位移。这个数量是该示例的取舍，需按产品内容和空间重新决定。

来源：[S02 · 堆叠通知](https://cantrip.cn/i/stacked-toasts) / [示例源码](https://cantrip.cn/code/stacked-toasts)。

### P07：按意图显示辅助信息，避免打断熟练操作

“按住显示快捷键”等待约 600ms 才显示提示；期间按下其他组合键则取消提示，松开修饰键或失去焦点后收起。延迟区分“想查看提示”和“正在使用快捷键”。

适合快捷键较多的桌面工具。迁移时重新选择平台按键，避开浏览器和操作系统快捷键，处理输入框、中文输入法组合输入、窗口失焦和按键重复。另保留点击可达的帮助入口，手机用户也应能了解相关操作。

来源：[S02 · 按住显示快捷键](https://cantrip.cn/i/hold-shortcut-hint) / [示例源码](https://cantrip.cn/code/hold-shortcut-hint)。600ms 是参考参数，需针对产品测试。

### P08：把图标运动与控件行为分开

图标可以通过描边、旋转、形变、位移或填充表现状态；按钮与链接继续承担点击、键盘、表单和焦点语义。静止状态也应能辨认图标与动作。

一个控件可以包含多层运动，但每个节点、每个动画属性应有明确所有者。例如按钮层负责按压，内部 SVG 负责图形变化，避免两个动画系统同时写同一层的 `transform`。

同组图标统一光学大小、笔画、留白与静态姿态。选择 Lucide、Huge 或其他体系是项目决定，不因参考站提供两个系列就混用。装饰图标不重复播报，纯图标控件仍要有可访问名称。

来源：S01 的图标组件与控制接口；结合实际控件迁移需求整理。

### P09：在完整页面中决定细节是否成立

先用真实结构和合成内容安排导航、主任务、正文、辅助信息与操作，再放入候选组件。展示页中的大图标、留白、居中演示和弹簧参数不直接成为产品规格。

整页检查应覆盖主入口、内容层级、中文与英文、长短文本、空态与失败态、窄屏与短窗口、深浅色和文字缩放。密度通过信息组织、操作收纳与空间分配改善，同时保留阅读与操作所需信息。

本条是用于后续设计的综合方法。当前三站的组件源码不能证明某个完整页面已经达到视觉目标，也不能代替用户判断。

## 4. 来源笔记与实际复用边界

### S01 · AnimateIcons：图标动效候选

入口：[官网](https://animateicons.in/) · [文档](https://animateicons.in/icons/docs) · [React](https://animateicons.in/icons/docs/react) · [仓库](https://github.com/Avijit07x/animateicons)

本次源码固定于 `8997a4e4084e54c9001c1290e1a785a1817a5065`。这是研究时取得的仓库 HEAD，未建立它与官网部署或 npm 已发布产物的一一对应关系。

**已确认：** 官网和文档提供 Lucide、Huge 两个图标系列，以及 React、Vue、Angular 和原生 JavaScript 接入说明。图标支持大小、颜色、`duration`、`isAnimated` 等参数；有默认悬停播放和 `startAnimation()` / `stopAnimation()` 控制接口。可安装包，也可取得单个 React 图标源码。

本次抽查的 [Bookmark](https://github.com/Avijit07x/animateicons/blob/8997a4e4084e54c9001c1290e1a785a1817a5065/icons/lucide/bookmark-icon.tsx) 用纵向位移与横纵缩放构成反馈，[Check](https://github.com/Avijit07x/animateicons/blob/8997a4e4084e54c9001c1290e1a785a1817a5065/icons/lucide/check-icon.tsx) 组合描边偏移、缩放与透明度；两者都读取 `useReducedMotion`。其中 `duration` 乘在基础时长上，值越大动画越慢，不能当成统一的秒数。

**可借用：** 成功反馈中的勾线、收藏动作后的短反馈、由真实控件驱动的图标运动。图标常态与运动之间有明确关系，比给任意图标统一加旋转更容易表达动作。

**迁移时处理：**

- 抽查组件外层为 `m.div`，默认处理鼠标进入与离开；它不是完整按钮。键盘、触屏和业务成功时机由项目控件负责连接。
- 源码中的减少动态效果分支不等于已验证运行中切换偏好、快速重入和所有图标的行为。
- 所查 [React 包声明](https://github.com/Avijit07x/animateicons/blob/8997a4e4084e54c9001c1290e1a785a1817a5065/npm/package.json) 支持 React 18/19，构建使用 Motion 14；样例使用 `domMin`。现有项目使用其他 Motion 版本时，应核对 API 与打包方式，不能假定直接复制即可运行。
- 全站介绍中的数量和兼容性声明不是本项目的包体积或运行验证结果。集成时按实际导入范围测量。

**许可：** 项目 [MIT](https://github.com/Avijit07x/animateicons/blob/8997a4e4084e54c9001c1290e1a785a1817a5065/LICENSE)；图形另有 [第三方声明](https://github.com/Avijit07x/animateicons/blob/8997a4e4084e54c9001c1290e1a785a1817a5065/THIRD_PARTY_NOTICES.md)，包括 Lucide 的 ISC、部分 Feather 来源的 MIT，以及 Hugeicons 免费图标的 MIT。复制代码或图形时保留适用声明。

关于页区分“原作”“参考”“作者”和原创；部分条目提供本站重写的 Demo，部分仅展示作者发布的媒体。不能把所有条目称作本站原创源码，也不能把重写版当作原作者实现。

**已核实的实施边界：**

- 下载文件包含 Demo 运行时：画板缩放、模拟光标、脚本播放、暂停、重置与输入管理。产品组件只应抽取所需机制，重新安排生命周期，不能整体移植演示环境。
- 渐进树导航使用内置 `TREE`，递归创建全部节点，并按参考画板设置坐标。它证明了层级转换思路，尚不是支持大量节点、服务端搜索和分页的目录组件。
- 迷你上传列表通过帧时间推进模拟进度；减少动态效果分支会直接设置为完成。这属于展示逻辑，真实上传或后台任务必须由实际结果决定状态。
- 通知示例包含剩余时间、展开和滑动状态。键盘阅读是否暂停、持续错误如何保留、如何进入完整任务记录，需要在产品里另行设计和验证。
- 快捷键示例含平台修饰键和失焦清理。移植到有输入框的页面，还需检查编辑快捷键、输入法与全局事件范围。

**暂不用于 Facetmark 主工作区的方向：** 黑洞扭曲文字、物理标签堆、大面积粒子或依赖悬停的立体展示。这些可留作品牌页、作品集或展示页面的候选；判断依据是使用场景，并非禁止表现力。文件夹、胶囊等效果被收录，也不恢复本项目已否定的视觉方案。

**许可：** 所查关于页和这 5 份下载文件提供原作署名及来源，但本次没有找到覆盖这些 Demo 的明确通用代码许可证。当前收录其设计机制与引用；直接复制代码或媒体前，再核查对应授权。可下载与有署名不等于已获得任意再分发许可。

| [Multi Step Form](https://github.com/iurvish/uselayouts/blob/f1a066916515193336cbdb09f817aa42d888a0e2/registry/default/example/multi-step-form.tsx) | 表单数据由上层维护；步骤方向与内容高度参与过渡 | “下一步”直接切换，最终才调用提交校验；提交示例只记录数据并显示 toast。需补齐按流程所需的校验、错误定位、真实提交、未保存状态与原生表单行为。 |
| [Accessible Action](https://github.com/iurvish/uselayouts/blob/f1a066916515193336cbdb09f817aa42d888a0e2/registry/default/example/accessible-action.tsx) | 卡片拖拽、倾斜和移到堆栈后方的对象关系 | 实际导出的是 CardStack；名称不能证明无障碍完整。该文件导入 `framer-motion`，而 registry 声明 `motion`，复用前需核对依赖。当前仅作展示型交互候选。 |

**依赖取舍：** Multi Step Form 的 registry 列出表单、校验、日期、通知、测量等依赖，源码还引用项目 UI 文件。已有成熟表单体系时，优先迁移结构与反馈方式，再决定是否需要额外依赖。包体积、Motion 版本兼容与完整依赖闭包本轮未运行验证。

## 5. Facetmark 的应用候选

本节仅适用于当前项目，不作为其他软件的默认规范。

2026-10-22，用户对 PR #44 当前界面提出新的否定并要求重构规划，随后要求先建立这份可持续补充的设计文档。上一轮助手提出的统一侧栏、内容列表、按需阅读面板和配色建议仍是方案候选，没有因此成为用户认可的视觉系统。

| 顺序 | 产品位置 | 候选机制 | 必须保留的产品行为 |
| --- | --- | --- | --- |
| 优先 | 收藏工具栏与单条操作 | P02 菜单定位、P05 渐进展示；吸收 Dynamic Toolbar 的内容测量方式 | 新增、管理、生成摘要与处理范围清楚分离；跨页选择不丢失；隐藏操作能被键盘和触屏访问 |
| 优先 | 模型连接、导入和任务 | P03 原位状态反馈、P08 图标反馈 | 发现、选择、测试、保存和执行仍为独立状态；变更模型后重新测试；失败可恢复 |
| 优先 | 文件夹选择器 | P04 当前层与祖先路径 | 搜索完整目录、精确选择、服务端分页；浏览层级与选择目录不混淆 |
| 随页面设计评估 | 设置与处理前确认 | S03 分步结构和定向过渡 | 草稿、校验结果和测试状态持续存在；保留范围确认与处理同意 |
| 随页面设计评估 | 短反馈与任务入口 | P06 通知堆叠与阅读暂停 | 持久任务、失败记录及原任务快照恢复仍有固定入口；不遮住分页和阅读末尾 |
| 后续增强 | 高频键盘操作 | P07 延迟快捷键提示 | 兼容 Windows、中文输入法和现有快捷键；提供直接可见的帮助入口 |

先完成真实收藏页的完整构图和操作路径，再判断这些细节是否加强了整体。组件画廊不能代替整页方案，也不能通过安装新图标包解决导航和内容层级问题。

工程迁移沿用现有 React、HeroUI/React Aria 控件与数据流程。每个组件明确样式和动画归属，替换时移除旧定义。若决定引入源码或依赖，再核对具体版本、许可、控件语义和运行表现。

本项目仍遵守本地轻量编辑与静态检查、云端构建和浏览器验证的边界，使用隔离合成数据。此手册不授权提交、推送、发布或访问真实浏览器资料。


## 7. 将参考转成开发说明

给设计者或开发者的说明，应同时包含效果、行为和验证条件。可以在新项目直接使用以下模板：

```text
请先读取本项目的产品说明与设计约定，再参考这份手册。
本次页面：……；用户主要任务：……；内容与数据规模：……。
采用条目：Pxx / Sxx 的具体机制。
视觉目标：描述整页构图、字阶、色彩与材质关系；使用项目的设计变量。
操作过程：如何触发、展开、返回、取消、失败和重试。
保留行为：原生链接、键盘、焦点、表单、数据范围及上下文。
边界状态：窄屏、长文本、中文输入、快速切换、减少动态效果。
实现边界：沿用哪些控件和数据逻辑；哪些旧样式应随迁移删除。
验证：在允许的环境里检查完整页面和真实路径，分别报告行为与视觉结果。
```

例如菜单需求可以写为：“在现有菜单控件上，使面板以触发器位置展开；键盘连续移动时选中反馈即时到位。关闭后焦点回到触发器，关闭动画中的菜单立即停止接收输入。保留窗口边缘定位和减少动态效果方案。”随后再决定符合本项目节奏的时长、位移和阴影。

## 8. 后续资料优先补充什么

为了使手册真正支持完整软件与网站设计，后续优先补充：

- **完整应用页面：** 导航、工具栏、内容区、详情区如何配合，窗口缩小时如何重新组织。
- **中文排版：** 中英混排、长标题、多级说明、数据密集列表和文字缩放。
- **主题与材质：** 深浅色的层次、状态色、图标一致性，以及有表现力但可读的完整界面。
- **真实流程：** 首次使用、空态、错误恢复、长任务、设置草稿和返回上下文。
- **不同网站类型：** 产品官网、个人主页、文档站与作品集各自的内容组织，避免将同一工作台结构套到所有网站。

后续资料先补足这些缺口；新动效也可以继续收录，但需说明它带来的新机制或适用场景。
