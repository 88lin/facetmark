# W4：意图抽取的人工判读（协议先行）

W1 报告 §9.4 第 3 条：**抽 50 篇人工读意图抽取的输出，判断 F2 的失败是 3B 模型不够，
还是「让模型预写用户可能怎么问」这个理念本身不成立。** 这是四周计划里唯一一件可能
推翻项目核心假设的事，也是唯一一件不需要写代码的。

这一页分两部分：**协议**在看数据之前写完并落盘，**结果**在之后追加。中间没有回头
改协议。判读记录逐条落在 `eval/w4-intent-read.jsonl`，任何人都可以重新打分。

---

## 1. 协议（在抽样与判读之前固定）

### 1.1 抽样

- 总体：`intent_query` 表里 `kept = 1` 的全部记录（自检探针保留下来的那 9,475 条）。
- 抽样框按 `id` 升序固定，用 `random.Random(20260803).sample(ids, 50)` 抽 50 条。
  种子写死在这里，不是抽完再填的。
- 每条记录连同它所属书签的 `url` 与 `title` 一起呈现给判读者。

### 1.2 判读者

**判读者是这套系统的 LLM 助手本身，不是这个书签库的主人。** 这比 §9.4 设想的
「人工读」弱一档：真正有资格说「我会不会这么搜」的只有存下这些页面的那个人。
所以逐条记录全部落盘，判读者的每一个打分都可以被推翻。这一节的结论应当读作
**上界**——一个不认识库主人的判读者觉得「会」的比例，库主人只会更低。

### 1.3 评分标准（三档，看数据前写死）

对每条「页面 + 抽出来的意图查询」判一个等级：

- **会**：这句话是这个页面的**持有者**在几周后想找回它时，可能真的敲进搜索框的。
  判据有两条，要同时满足：
  1. 它描述的是**「我当时要解决什么问题 / 我为什么存它」**，不是这一页的内容摘要；
  2. 它**不需要判读者已经看过这一页**——不含只有读过才知道的专有名词、版本号、
     作者名、产品代号。
- **勉强**：能想象有人这么搜，但它更像是**在已知答案的前提下反推出来的**——例如
  标题的同义改写，或者塞进了页面里的专有名词。检索时它当然能命中，但那是因为它
  抄了答案，不是因为它预测了问题。
- **不会**：不是一个人会敲进搜索框的东西。典型形态：陈述句或摘要句、带
  markdown/编号、长到不像查询、通用到能指向库里任何一页、或者干脆与页面内容不符。

### 1.4 判定规则（看数据前写死）

- **「会」的比例低于 50% → 判为理念问题**，不是模型大小问题。换更大的模型可以让
  措辞更像人话，但换不掉「模型在为一个它并不认识的人预写问题」这件事。
- 「会」≥ 50% 且「不会」≤ 20% → 判为**实现问题**，值得用更大的模型再试一次。
- 落在中间 → 不下判断，扩大样本到 150 条再读一次。

### 1.5 这一节不做什么

不重跑检索、不比较档位、不改任何阈值。W1 的 479 条查询里有一部分就是从
`intent_query` 派生的，因此**任何在这批数据上得出的检索指标都不能用来支持或反对
本节的结论**，本节也不引用。

## 2. 结果

逐条记录在 `eval/w4-intent-read.jsonl`（50 行，字段 `n / id / url / title / text /
probe_rank / grade / borderline / note`），可以直接对着重打分。

**先说这一节的可信度边界。** 协议与结果落在同一个提交里，所以 git 历史证明不了
「协议写在看数据之前」，你只能听我说。能被独立核验的是另外三件事：

1. **抽样可复现。** `kept=1` 的总体是 9,475 条，`random.Random(20260803).sample(ids, 50)`
   重抽一次得到的 50 个 id 与 `eval/w4-intent-read.jsonl` 里的**完全相同**（已核验；
   文件按 `id` 升序呈现，`sample()` 的原始顺序被排序覆盖，集合一致）。
2. **判定阈值和三档标准是可检查的文字**，不是事后拟合的分数线；
3. **结果没有落在阈值边缘**——38% 对 50%，差 6 条。

### 2.1 计数

| 档 | 条数 | 占比 |
|---|---|---|
| 会 | 19 | 38% |
| 勉强 | 21 | 42% |
| 不会 | 10 | 20% |

**「会」= 38% < 50%，按 §1.4 判为理念问题。**

判定的稳健性只往一个方向倒：19 条「会」里有 5 条自己标了 `borderline`（第 3、25、
36、40、48 条），全部降级则「会」= 28%，判定不变。要翻案需要把 21 条「勉强」里的
6 条重读为真——而「勉强」这一档正是为了拒绝这种重读才在看数据之前写死的。

### 2.2 失败有固定形态，而这个形态换模型换不掉

彻底错的只有 20%：编造使用场景（第 5 条「trending papers in my inbox」）、与页面
内容不符（第 6、23、39、44 条）、把发文域名当成产品名（第 30 条 Bosun）、把文章
内部的比喻当查询（第 34 条「mugs vs hypercubes」）。**这一档是更大的模型能修的。**

占比最大的是「勉强」，42%，而且形态高度一致——**它们都是在已知答案的前提下反推的**：

- 逐字或近逐字复制标题：第 42 条（只少一个问号）、第 45 条（一字不差）、第 18、12 条；
- 产品名 + 泛后缀：第 7 条 `Bun Shell features and usage`、第 47 条
  `concrete.css documentation`、第 13 条 `WordStack game`；
- 抄页面里的专有名词：第 31、37、43、49 条。

**更大的模型只会把标题改写得更漂亮。** 模型能看到的只有这一页，它写不出「这个人
当时为什么存它」——那份信息根本不在页面里，它在存的人脑子里。这是结构性限制，
不是容量限制。所以 §1.4 那条规则指向的结论，不是「3B 不够，换 32B 再试」。

### 2.3 那 19 条「会」不是随机分布的

19 条里有 11 条落在同一种情形：**标题本身没用**——

`Demo`（第 16 条）、`维基百科`（26）、`介绍文章`（40）、`一篇解读`（32）、
`Substack 周刊`（33）、`一个老外的观点`（1）、`themessenger.com`（28）、
`diagrams.net`（24）、`Calibre`（27）、`GPTAnywhere`（22）、`1-800-ChatGPT`（20）。

在这些页面上，意图查询实际做的事是**补一个像样的标题**，不是预测提问。这给出一个
比「关掉 F2」更小、更可测的假设：

> **意图抽取的价值可能集中在标题退化的页面上。** 把它当作标题修复（一个 enrich
> 字段），而不是当作一个独立的检索面。

这条只登记为假设，不改任何默认值。验证它需要 W2 的新查询集：只对标题信息量低的
页面建意图向量，与全量建对比。

### 2.4 一个推论，以及它的检验

如果 42% 的意图查询是标题的改写，那么意图向量在很大程度上应该**贴在内容向量上**，
于是意图面的邻域应该就是内容面已经找到的那些文档。这个推论不需要模型也不需要
查询集就能测：用**同一个向量**（每篇书签自己的内容向量）同时探两个面，去掉探针
文档自身，数两个 top-10 邻域重合多少。

`scripts/facet_overlap.py`，全库 2,376 个探针，k=10，交付库快照：

| 对比 | top-10 重叠 |
|---|---|
| **意图面 vs 内容面** | **26.9%** |
| 词面 `lex_seg` vs 内容面（参照） | 10.6% |
| 随机（10 / 2,376） | 0.4% |

还有一条更直白的：2,376 个探针里 **2,367 个（99.6%）**，在 9,475 条意图向量中离
一篇文档的内容向量最近的那条，就是**它自己生成的意图查询**。意图空间基本贴在
内容空间上。

三个数要一起读：

1. 意图面**不是**内容面的复制品。26.9% 不是 90%，73% 的邻居确实是不同的文档。
2. 但它与内容面的相关性是一个真正不同的面（词面）的 **2.5 倍**，是随机的 64 倍。
3. 而 W1 §4.1 说：把意图面加到内容面上是 **−5.43pp**（overall R@5 0.643 → 0.589），
   与加两个词面的 −5.43pp 分毫不差。那 73% 的「不同」没有变成增益。

合起来：意图面交回来的不是一个新视角，是**四分之一重复 + 四分之三不更好**。RRF
为这两部分都付了钱——重复的那部分让它给内容面的答案重复投票，不同的那部分是噪声。

**这个实验不能证明的**：探针是文档向量，真实检索的探针是问题向量。重叠高只说明
在这个库上两个面的邻域大量重合，不说明意图面在真实提问下没用。要判那一点仍然
需要新查询集。

### 2.5 这一节改了什么、没改什么

- **没改默认值。** 交付默认档 `FULL` 本来就只开内容面；`FUSED`（没有 API key 时的
  回退档）仍然四面全开。这一节不动它们。
- **没删代码。** 意图抽取仍在索引流程里。结论是「**作为一个独立的平权检索面**，
  这个理念不成立」，不是「这些文本一无是处」——§2.3 给了另一种用法。
- **给 W2 多加了一个问题**：只在标题退化的页面上建意图向量，会不会比全量建更好。
- **判读者是 LLM 不是库主人**（§1.2），所以 38% 是上界。真正的持有者只会判得更低。
