# 门控漏响率的检验协议

**这份文件写在用 v3 查询集跑任何一档之前。** 判定规则、处置方案、以及「漏响率多少
算不可接受」都在这里定死，先后可从 `git log` 外部核对。本协议是
`docs/gate-precision-protocol.md` 的镜像：那里测的是门控**误响**的一面，这里测的是
**漏响**的一面。两面都量过，才谈得上这个门控值不值得再上线一次。

---

## 0 为什么现在写这个

门控精确率实验（`docs/gate-precision.md`）回答的是「不该开的时候开了要付多少」：
361 条对抗探针上 −18.83pp，`gate_v2` 把裸年份那一支修到 −0.50pp。那份报告的 §7 和
ROADMAP 的 W4 同时写明：实验只测了误响的一面。

漏响的一面已经有定性证据。真实库演示（`docs/real-library-demo.md`）里，「上次存的
那个签到脚本」**没有**被判成情景查询——「上次」在 `gate_v2` 的 `_SAVE_ACTION` 里，
却不在 v1 的 `_VAGUE_EPISODIC` 里。也就是说：用户明明白白在说「找我保存过的东西」，
门控的词表却接不住。这不是孤例的风险，而是机制性的：**用户表达保存意图的自然词汇，
大半已经被门控征用为触发词；剩下的那部分，门控一个都不认识。**

要量它，需要一批**确实在找某次保存动作、却不含年份也不含现有词表**的查询。这正是
v3 查询集的 `q_save_action` 类型（构造规则见 `docs/v3-query-set-protocol.md` §3）。
这批查询在生成时就逐条对照三张词表拒绝过触发词，所以门控在它们上面的任何触发都是
误响，任何不触发都是漏响——**两面在同一批查询上同时可读**。

## 1 这份协议要回答的问题

> 在每一条都表达「找我保存过的东西」、却不含任何门控触发词的查询上，门控的漏响率
> 是多少？漏响让这些查询付多少 Recall@5？

明确**不**回答：这类查询在真实使用中占多大比例。与精确率协议同理——频率需要真实
查询日志，本项目没有。这里给出的是**单价**，不是总账。

## 2 探针查询集

v3 查询集（`eval/queries/v3-holdout.jsonl`）中 `qtype = q_save_action` 的全部记录。
构造协议已保证：

1. 每条都表达保存动作意图（提示词要求，校验器不查内容重叠）；
2. 每条都不含 `_ABS_YEAR` / `n_ago` / `time:relative` / `_VAGUE_EPISODIC` /
   `_SAVE_ACTION` 的任何成员（`check_save_action` 逐条拒绝）；
3. `classify()` 在生成时**没有**被用作过滤器——门控开不开火是结果变量。

**规模**：v3 构造协议 `--save-action-share 0.15`，4 块 × 64 目标，期望 30–40 条
`q_save_action`（每目标最多一条，丢弃率未知）。**接受 ≥ 25 条即执行判定**；不足
25 条则只报描述性数字，不下判定，把功效不足写在结论旁边。这个下限低于精确率协议
的 200，因为漏响率是一个**比例**（0–100%），25 条的 Wilson CI95 半宽约 ±18pp，
足以区分「门控全接住」与「门控全漏掉」这两个极端；Recall@5 代价的配对检验则按
实际条数报告 mde。

## 3 跑哪两档

与精确率协议同一对：`A` 与 `A_gatedctx`，同一份库、同一时钟、同一批查询。两档的
唯一差别是门控加上下文乘子，所以差值不掺别的东西。

**但注意一个不对称**：精确率实验里门控触发是**代价**的来源（窗口错），这里门控
**不触发**是代价的来源（该拿的上下文乘子没拿到）。所以主指标的方向与精确率协议
相反。

## 4 判定规则（在看到任何数字之前）

**主指标一：漏响率** = `q_save_action` 中 `classify()` 未判为 episodic（或判了但
`episodic_beyond_a_bare_year` 为假）的比例，Wilson CI95。

**主指标二：配对 ΔRecall@5 = A_gatedctx − A**，10,000 次配对自助 CI95，双侧精确
McNemar。两个主指标**联合**判定，不做多重校正（它们测的是同一个机制的两面）。

| 判定 | 条件 |
|---|---|
| **门控漏响不合格** | 漏响率点估计 ≥ 50% **且** ΔR@5 点估计 ≥ +2.0pp（A_gatedctx 更好）**且** CI95 下界 > 0 |
| **漏响但无代价** | 漏响率 ≥ 50% 但 ΔR@5 的 CI95 含 0 |
| **未发现漏响** | 漏响率 < 50% |

### 不合格时的处置（同样先写在这里）

1. **扩词表**：把 v3 生成时实际用到的、未被征用的保存动作说法（从冻结查询集里逐条
   读出来，不许凭印象写）加入 `_VAGUE_EPISODIC` 或 `_SAVE_ACTION`。
2. 扩词表后的门控要**同时**过两关才允许上线：
   - (a) 本探针集上漏响率降到 < 50% 且 ΔR@5 的 CI95 含 0 或上界 < 0（代价消失）；
   - (b) 门控精确率那 361 条上误响代价**不回升**：ΔR@5 vs `A` 的 CI95 下界仍 > −2.0pp。
3. **(a) 过、(b) 不过 → 词表不动，漏响率作为已知限制写进文档。** 一个靠把保存动作词
   全吞掉才能不漏响的门控，会把精确率实验刚修好的洞重新挖开。
4. 两关都过 → 新词表成为默认，版本号再走一次，`docs/gate-precision.md` 的结论段落
   跟着改。

### 一并报告的次要量（描述性，不判胜负）

- 触发率：整体、按 v3 的池（body / bodyless / dead-servable / dead-unservable）拆开；
- 只在**触发的**那一子集上的 ΔR@5——门控帮上忙的那部分；
- 未触发子集的 ΔR@5，它**必须是 0.00pp**：两档的唯一差别就是门控，不触发就不可能有
  差。这一格是这次测量自己的自检位，不为 0 说明实现或评测有问题，结论作废；
- 每条探针实际用到的保存动作说法（从冻结查询集读出），作为词表扩展的候选清单——
  **这是本协议唯一允许从结果里读出来的东西，且它的用途在 §4 已经定死**。

## 5 这份协议测不到什么

- **频率。** 探针集每一条都在找保存动作，是**对抗性构造**。它回答「这类查询每条付
  多少」，不回答「平均付多少」。
- **真实词汇。** 探针的保存动作说法是模型在「不许用词表」的约束下写的，未必是人会
  打的那一句。漏响率是**下界**：连这些词都不触发，真实词汇只会更多。
- **与精确率的联合最优。** 两关都过只是「不漏响也不误响」，不是「门控值得上线」。
  值不值得，要等 `gate_v3`（收窄 `time:relative`）自己的预注册跑完，三笔账合在一起
  才算。
