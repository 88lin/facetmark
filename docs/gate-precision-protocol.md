# 门控精确率的检验协议

**这份文件写在生成任何一条探针查询之前，也写在跑任何一档之前。** 判定规则、处置方案、
以及"不合格时默认值怎么退"都在这里定死，先后可从 `git log` 外部核对。

---

## 0 为什么现在写这个

1.2.0 把**带门控的上下文乘子**开成了默认档 `full` 的一部分。依据是 616 条没有参与提出
这个假设的查询：整体 Recall@5 +3.09pp，CI95 [+1.79, +4.55]，19 胜 0 负
（`docs/gate-w2w3.md`）。

那份报告的 §7 同时写明了它**没有**检验什么：门控有两面，

- **召回面**——该开的时候开。情景型查询 224/224 全部触发，收益 +8.48pp。这一面测过了。
- **精确面**——不该开的时候关。内容型查询 1/181 触发（0.55%），模糊型 0/211。**这一面
  没有测过**，因为那 616 条里的情景型查询在生成时就用产品自己的 `classify()` 校验过
  时间短语，"门控触发的集合 ≈ 情景型标签"大半是**构造出来的**；而内容型那一支在生成时
  被明确要求不许写日期。整批查询里几乎没有"带时间词但问内容"的样本，0.55% 因此**不能
  外推**。

赌注是明确的，因为代价已经被 W1 量过：内容型查询上**无条件**开上下文乘子是
**−9.94pp**，CI95 [−14.62, −5.26]。如果真实使用中"2015 年那批论文"这类查询比 0.55%
常见得多，那么 1.2.0 的默认值就是在拿这些查询的损失换情景型查询的收益，而这笔交换
从来没有被称过重量。

## 1 这份协议要回答的问题

> 在**每一条都带时间表达、但意图是问内容**的查询上，门控开火要付多少 Recall@5？

明确**不**回答：这类查询在真实使用中占多大比例。那需要真实查询日志，本项目没有，也
不打算靠猜。频率未知时，这个协议给出的是**单价**，不是总账。

## 2 探针查询集

### 目标页

库 `library-w1-indexed.db`（与 W1、W2/W3 同一份快照）里满足全部条件的页面：

1. 有正文，`char_count >= 300`；
2. 正文里出现 1990–2025 之间的四位年份；
3. 该年份 **≠ 这条书签的保存年份**——这是探针的要害：查询里的年份指向内容，而门控会
   把它当成保存时间去解析，于是窗口必然错。

按保存年份分层抽样（与主生成器同一函数），**每个目标最多产出一条查询**：两条同源查询
不独立，会让配对自助低估方差。

### 两个子类

种子决定，比例 60 / 40：

| 子类 | 查询里必须带 | 它模拟的真实场景 |
|---|---|---|
| `p_year` | 那个**内容年份**（不是保存年份） | "2015 年那批论文讲的什么" |
| `p_relative` | 一个相对时间词（最近 / 近两年 / 去年 / recently / last year …） | "最近几年的研究进展那篇" |

语言跟随目标页标题，与主查询集同一规则。

### 校验器

拒绝即把理由喂回模型重试，最多 3 次，之后丢弃并计入丢弃率：

1. 主查询集 `check_content` 的**全部**门槛：不是标题换个词、至少含一个正文里的词、
   示例不许穿帮、语言一致、不是逗号分隔的关键词串。
2. `p_year`：查询必须含那个内容年份，且它 ≠ 保存年份。
3. `p_relative`：查询必须命中相对时间词表。
4. **不许出现保存动作词**：保存 / 收藏 / 存的 / 书签 / 上次 / 那天 / 那阵子 / 当时 /
   saved / bookmarked / i saved 之类，出现即拒。一旦查询说的是"我保存的"，它就变成了
   情景型查询，测的也就不再是精确率。
5. **不用 `classify()` 过滤。** 门控开不开火是**结果变量**，不是入选条件。这是本协议与
   W2/W3 情景型生成器最关键的一处不同——那里 `classify()` 是入场券，这里它是被测对象。

### 规模与停止规则

从 **400 个目标**生成，接受 **≥ 200 条**即执行判定。实际接受数、丢弃率、以及 80% 功效
下的最小可测差（与 W2/W3 同一公式 `(z_{0.975}+z_{0.8})·√disc/n`）一并报告。

**不因为结果不好看而补生成，也不因为结果好看而提前收工。** 接受数低于 200 条同样按下面
的规则判，只是把功效不足写在结论旁边。

## 3 跑哪两档

`A` 与 `A_gatedctx`，同一份库、同一时钟、同一批查询。

两档之间唯一的差别就是这个门控加上下文乘子，所以差值不掺别的东西。`A` 能代表 1.1.0 的
默认排序，依据与 `docs/gate-w2w3.md` §1 相同：W1 实测 `A -> A_graph` = +0.00pp 且零条
不一致，图扩展不改排好的那一页。

## 4 判定规则（在看到任何数字之前）

主指标：配对 **ΔRecall@5 = A_gatedctx − A**，10,000 次配对自助 CI95，双侧精确 McNemar。
**单一主检验**，因此不做多重校正。

| 判定 | 条件 |
|---|---|
| **门控精确率不合格** | 点估计 ≤ −2.0pp **且** CI95 上界 < 0 |
| **未发现代价** | CI95 含 0 |
| **反而有益** | CI95 下界 > 0 |

### 不合格时的处置（同样先写在这里）

看完数字再挑补救方案，等于给自己发一张事后合格证。所以处置也是预注册的：

1. **收窄成 `gate_v2`**：裸年份不再单独构成情景信号——`time:absolute_year` 必须与情景
   标记词或保存动作词同时出现才算数；`n_ago`、`time:relative`、`episodic_marker` 三条
   规则保持不变。
2. `gate_v2` 要**同时**过两关才允许上线：
   - (a) 本探针集上代价消失：ΔR@5 的 CI95 含 0 或下界 > 0；
   - (b) W2/W3 那 616 条上收益仍在：ΔR@5 vs `A` 的 CI95 下界仍 > 0。
3. **(a) 过、(b) 不过 → 默认值退回 1.1.0 的无门控行为。** 一个只有靠留着有害触发规则
   才能赢的门控，不是门控，是一个把两类错误打包卖的开关。
4. 两关都过 → `gate_v2` 成为默认，版本号再走一次，`docs/gate-w2w3.md` 的结论段落跟着改。

### 一并报告的次要量（描述性，不判胜负）

- 触发率：整体、按子类、按 `rule_hits` 拆开；
- 只在**触发的**那一子集上的 ΔR@5——这是"单价"的更干净读数；
- 未触发子集的 ΔR@5，它**必须是 0.00pp**：两档的唯一差别就是门控，不触发就不可能有差。
  这一格是这次测量自己的自检位，不为 0 说明实现或评测有问题，结论作废。

## 5 这份协议测不到什么

- **频率。** 探针集每一条都带时间词，是**对抗性构造**。它回答"这类查询每条付多少"，
  不回答"平均付多少"。
- **相对时间词的双向性。** `p_relative` 里若目标恰好保存在窗口内，门控会**帮忙**。这不是
  缺陷而是真实行为，但它会稀释代价的点估计——所以两个子类分开报，不只报合计。
- **生成器的口味。** 查询仍由 `z-ai/glm-5.2` 写，与 W2/W3 同一个模型、同一批系统性偏好。
  它写出来的"带年份的内容查询"未必是人类会打的那一句。
- **库还是那个库。** 2,376 条公开语料快照，不是任何人的真实书签。

## 附录 A：实现与协议对齐（2026-08-04，写在生成第一条查询之前）

把 §2 落成代码时发现三处实现与上面这份文本不一致。三处都在**任何一条探针查询被生成、
任何一档被跑之前**订正，改的是实现，不是规则——§4 的判定表、处置方案、次要量一个字没动。
先后同样可从 `git log` 外部核对。

**A.1 年份区间收回 1990–2025。** 实现里写成了 `1990–2029`，比 §2 宽。收窄回协议原文。
2026 是这份库自己的"现在"（`meta.created_at` = 1785649110），内容年份 2026 与保存年份
2026 在意图上不可区分，而整个探针恰恰建立在这个区分上。

**A.2 删掉一条协议没写的额外守卫。** 实现里额外要求那个年份在正文出现 **≥ 2 次**，用来挡
`© 2024` 这类页脚。在库上量了一下代价：

| 入选规则 | 合格页面 |
|---|---|
| §2 字面（正文含该年份，≠ 保存年份，`char_count >= 300`） | 698 |
| 加"该年份须出现在模型看得到的 `body[:2500]` 里" | **468** |
| 再加"须出现 ≥ 2 次" | 195 |

这条守卫砍掉 58% 的候选框，而抽样读了被它砍掉的页面，绝大多数是货真价实的主题年份——
"lava tubes were discovered in 2009"、"dating back to 2012"、"the Chicago Tribune
explained in 2019"。它比协议严，代价是一半以上的功效，而它想挡的噪声是**配对噪声**，在
两档之间会抵消。删掉。

保留的那条（年份必须落在 `body[:2500]`，即模型实际看到的那一段）不是取舍而是必需：让模型
写一个它看不见的年份，产出的不是探针，是编造。这条在附录里写明，因为它使实际入选口径比
§2 字面窄，从 698 收到 468。

按 468 的框，§2 的"从 400 个目标生成"是可达的，因此停止规则走的仍是 ≥ 200 那一支；实际
接受数、丢弃率、mde 照常报告。

**A.3 同分时取"窗口最错"的那个年份。** 一页提到多个年份时，先按出现次数，次数相同则取
**离保存年份最远**的那个。这是把 §2 自己的构造当真：探针的要害是门控解析出的窗口必然错，
那么页面给出选择时就取最错的那个。实际取到的 400 个目标里，内容年份与保存年份的距离
p25/p50/p75 = 2 / 5 / 14 年。距离分布与"按距离分组的 ΔR@5"作为**描述性**次要量一并报告，
不参与判定。

**A.4 一段被证伪的防护代码。** 实现里曾经过滤示例里的数字 token，理由是"查询写了被要求写
的那个年份，会被鹦鹉学舌检查当成抄示例"。它不会：鹦鹉检查是
`(查询词 ∩ 示例词) − 页面词`，而 `content_year()` 只会返回页面里出现过的年份，于是那个
年份总会被减掉。已删，替换成一条把这个结构性理由钉住的测试
（`test_the_required_year_cannot_be_parroted`）。
