## 并发与重试的实际含义

| 设置 | 默认 | 范围 | 执行边界 |
| --- | ---: | ---: | --- |
| 摘要并发 | 4 | 1–64 | 摘要任务同时在途条目，Agent 调用还受 Agent 额度约束。 |
| Agent 并发 | 2 | 1–8 | 同一服务进程、数据目录和 Agent 的摘要/聊天 provider 共用实际调用槽。 |
| 聊天并发 | 2 | 1–8 | 同时运行的对话；Agent 模式还取与 Agent 并发的较小值。 |
| 抓取总并发 | 30 | 1–64 | 正文任务的总在途请求；网站扫描批次也不超过此值。 |
| 每站点并发 | 2 | 1–16 | 同站点抓取槽，重定向后的实际请求重新获取目标槽。 |
| 每站点最小间隔 | 0.5 秒 | 0–60 秒 | 已保存设置作为最低间隔，robots 延迟仍受原有策略约束。 |
| HTTP 总尝试次数 | 3 | 1–10 | 包含第一次；身份/权限等确定失败不重复。 |
| 每分钟请求数 | 0 | 0–6000 | 0 表示不限；同进程内，同数据目录/端点/账号的 provider 共用滚动 60 秒额度，每次尝试、重试和兼容回退均计数。 |

这些限制不跨独立操作系统进程、不同数据目录或不同 Agent 合并，不自动上调用户
并发。`Retry-After` 支持秒数和 HTTP 日期，不把服务器要求的 120 秒缩成 60 秒；
429/503 冷却即使当前请求耗尽尝试，也影响下一次请求。过长冷却返回稍后再试，等待可取消。

收尾核对还发现桌面摘要队列保留了 Agent 批次固定 2 的旧限制。现改为摘要上限与
Agent 上限的较小值，并用真实 JobRunner 和共享 Agent quota、合成 CLI 回复验证
6/4、3/8、4/1 三组配置的同时执行数分别为 4、3、1；三项用例在当前四组 Python
云端回归全部通过。

聊天每题最多 4000 字符、每会话最多 200 条消息。模型只接收最近 12 条、最多 24000
字符的有效历史和最多 24000 字符的保存片段。当前后台 JSON 回答与状态轮询，不声称
逐 token 输出。来源记录保存内容指纹和更新时间；删除、隐私排除或无法映射的旧来源
不会作为下一次对话的历史证据发送。

## 恢复与取舍

v1 JSON 或缺少双标记的文件继续仅导入元数据。v2 先校验，异常完整回滚；来源指纹
不匹配的过期摘要跳过并报告警告。删除来源保留历史网址和快照，预览不可用而原链接
仍可访问；缺失固定来源不会让单篇对话扩成全库。未完成回复恢复为可重试的取消状态。
向量、密钥、浏览器状态、配置和任务日志不进入便携 JSON；这不是 SQLite/配置的整机
恢复包。共享文件夹同步的元数据契约没有扩大。

每项适用性见 [48 项功能、15 条执行路径与 9 个边界](githubstarsmanager-comparison-2026-10-25.md)，
原项目的桌面覆盖见 [桌面功能对照](desktop-feature-parity-2026-10-25.md)。参考固定
为 `2f41b01c79d9e4ed11752592fa4c6cbb837e342a`，依据源码而非截图。
GitHub Lists/Unstar/Fork 合并、远程工作流等专属写操作未搬入收藏核心。全文翻译、
feeds/WebDAV、可执行插件本轮未引入，具体理由和现有替代能力逐项写在对照表。
