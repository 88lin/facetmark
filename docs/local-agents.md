# 本机 Agent 摘要连接

在 **设置 → AI 连接 → 摘要来源** 选择 **本机 Agent · 使用已有登录**。
支持 Codex、Claude Code 和 OpenCode。自动模式按这个顺序选择已找到的程序，
界面显示实际选择；也可以指定一个 Agent。调用失败后不会暗中换用另一个账号或服务。

## 从模型发现到摘要

1. 检查 **选择 Agent** 与检测结果。**已检测到**只表示找到了可启动文件。
2. 在可见的 **摘要模型** 选择器中搜索并选择模型，或使用 **沿用 Agent 默认模型**。
   已知默认名称会直接显示。**手动输入**可填写完整 ID；OpenCode 使用
   `provider/model`。**刷新模型**可重新读取目录。
3. 点击 **测试连接**验证当前草稿，或点击 **测试并保存**在测试成功后保存。
   测试只发送固定文本，不发送收藏。结果显示被测试的 Agent／模型。
   若测试成功而保存失败，界面明确说明尚未保存。
4. 保存聊天连接后点击 **前往生成摘要**，或回到收藏页点击 **生成摘要**。
   在对话框选择范围、核对数量，并确认将哪些内容发送到模型服务。
   实际任务使用已保存并测试的模型；修改模型后需要重新测试。

切换 Agent 会保留各自模型草稿；摘要与向量的草稿、测试结果和保存状态相互独立。
切换连接身份或实际安装路径后，旧目录和连接结果失效。已保存的测试记录可跨后台重启
保留；仅在配置／实际命令指纹变化或缺少匹配的测试记录时，开始或继续模型任务前
需要重新测试相应连接。

## 模型目录的含义

| 来源 | 读取方式与限制 |
| --- | --- |
| Codex | 尝试已安装 CLI 的模型目录；不支持或读取失败时可使用本机缓存，并明确提示。读取配置中的默认模型。 |
| Claude Code | 显示 `sonnet`、`opus`、`haiku` 等别名与本机模型配置；这是别名／配置列表，不是账号可用权限清单。 |
| OpenCode | 合并 provider 配置中的模型与 CLI 目录，沿用可读取的默认模型；仅配置可用时显示对应提示。 |
| API 服务 | 在所填服务的 `/models` 读取目录，也可手动输入服务提供的模型 ID。 |

目录、缓存和别名都不证明模型可调用，实际访问权限以连接测试为准。目录为空、
读取失败或搜索无匹配时仍可手动输入；Agent 模式也可沿用默认后测试。
搜索支持方向键、Enter 选择、Escape 返回与鼠标操作。

## 安装、重新检测与失败恢复

| Agent | 运行方式 | 版本要求 |
| --- | --- | --- |
| Codex | `codex exec`，stdin 输入、JSON 事件 | 需支持 `--ephemeral --ignore-user-config --ignore-rules` |
| Claude Code | `claude --print`，stdin 输入、JSON 结果 | 需支持空工具集、严格 MCP 配置和禁用 hooks |
| OpenCode | `opencode run --format json --pure`，stdin 输入 | 以 1.19.0 验证，需支持这些非交互参数 |

探测检查进程 PATH、常用用户目录以及 npm、Bun、pnpm、Volta、Scoop、Homebrew
位置。Windows 还只读读取注册表中的当前用户／系统 PATH，减少桌面进程持有旧环境
导致漏检的情况。不会扫描整个磁盘或启动交互式 shell。npm 包装器解析为 Node
入口或原生程序，OpenCode 新版的 `opencode.exe` 不需要额外 Node 启动。

安装或更新后点击 **重新检测**。读取失败与未检测到是不同状态，所选 Agent 未找到
时不能测试。模型选择保持可见；**超时与安装位置**展开项显示探测路径和单次超时。
自定义安装目录应加入 PATH，再重新检测。

| 遇到的状态 | 下一步 |
| --- | --- |
| 未检测到所选 Agent | 安装并登录后重新检测，或显式选择另一个已安装 Agent。 |
| 目录读取失败／为空 | 刷新目录、沿用默认，或手动输入模型 ID 后测试。 |
| 登录、权限或连接失败 | 检查该 CLI 登录和模型服务；修正后重新测试同一选择。 |
| CLI 参数不兼容 | 更新 CLI 后重新检测、测试。 |
| 测试通过但未保存 | 重试测试并保存，确认保存提示后再启动任务。 |
| 摘要任务部分失败 | 从该任务继续／重试，保留完成项并只处理原快照的失败／未完成项。 |

## OpenCode 配置复用与执行边界

支持 `opencode.json`、`opencode.jsonc`、`OPENCODE_CONFIG`、
`OPENCODE_CONFIG_DIR` 和 `OPENCODE_CONFIG_CONTENT` 中的模型／provider 配置；
保留 JSONC 注释、尾逗号和相对凭据文件引用的语义。模型留空时沿用配置或 OpenCode
记住的默认值，显式选择则传递完整的 `provider/model`。

仅复用模型相关配置。摘要运行使用临时工作目录、临时会话数据库、禁止工具的独立
agent，关闭项目指令、外部插件、MCP 和会话分享。保留内置认证适配器，CLI 使用正常
认证存储，可以按自身流程更新 OAuth 凭据。Facetmark 不改写原配置，也不把凭据放入
命令行。依赖外部认证插件或 `wellknown` 组织远程配置的服务应使用 API 接入。

Agent 是模型服务客户端，不等于本机离线推理；摘要仍会发送到该服务。
每个 Agent 最多并发两次调用，超时与取消会终止子进程树。自动模式解析到不同程序后，
必须重新测试实际程序。

## 验证范围

当前验证证据与边界见[桌面验证记录](desktop-validation.md)。测试覆盖探测、配置隔离、
模型目录与选择、应用 HTTP 层测试／保存／任务调用、摘要存储及原快照失败恢复。
Actions 的真实 OpenCode 1.19.0 在 Linux 和 Windows 连接隔离模拟 HTTP 模型服务，
验证目录→指定模型→摘要传递、中文 stdin、无工具请求和原配置保持不变。
这些是集成协议证据，不证明个人账号、真实模型额度或摘要质量。
